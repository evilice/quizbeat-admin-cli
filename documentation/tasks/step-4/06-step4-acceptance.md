# Задача 6 — Приёмка этапа 4

Этап: 4 — Композиции.
Зависимости: [задача 3](./03-create-composition.md),
[задача 4](./04-composition-card.md) и
[задача 5](./05-delete-composition.md) (и транзитивно список из
[задачи 2](./02-compositions-list.md)).
Ссылка на ТЗ: [DoD раздела «Этап 4»](../../03-technical-specification.md#этап-4--композиции).

## Зачем

Задачи 1–5 по отдельности закрывают форму запроса и отказы на моке. DoD
этапа — другой контур: на живом `quizbeat-srv` черновик создаётся,
находится фильтрами, публикуется сменой статуса, после удаления не
виден в списке, снятие последнего тега шлёт пустой `tagIds`. Стык легко
остаётся зелёным в тестах, когда `tagIds` в query ушли повторяющимся
параметром или очистка тегов опустила поле. Новой функциональности
здесь нет.

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN`, учётки `ADMIN` и порта dev-сервера — общие
  для всех этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
  Для фильтра тегов на сервере должны быть хотя бы один-два тега
  (этап 3); при необходимости их заводят с экрана тегов в том же
  проходе.
- В сети создания без явной публикации нет поля `status` (или оно
  `DRAFT`) — сервер отдаёт черновик. Публикация — `PATCH` со
  `status: "PUBLISHED"` с карточки.
- Фильтр тегов в сети — один query-параметр `tagIds` со значением через
  запятую. Снятие последнего тега на карточке — в теле `PATCH` ключ
  `tagIds` со значением `[]`.
- Удаление в сети — `DELETE` и ответ `200` с `deletedAt`. Строка
  пропадает после повторного чтения списка.
- На карточке в проходе DoD в сети должен быть ровно один
  `GET .../full` на открытие (переход со списка, прямой URL, F5) и не
  должно быть повторного `GET /compositions` как источника данных
  карточки.
- `npm run test` гоняется один раз по всему `src/`. В выводе должны
  быть тест стора (`tagIds: []` в `PATCH`, `tagIds` одной строкой в
  query, разбор `full` с `null` аудио-полями), тест карточки (ровно один
  `GET .../full`, без повторного списка) и тест меню (пункт «Композиции»
  виден обеим ролям; «Теги» — обеим; «Сотрудники» — только
  `SUPER_ADMIN`). Отдельный прогон «только приёмочных» DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–5. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест, что `PATCH` с пустым набором
  тегов содержит `tagIds: []`, тест, что фильтр двух тегов даёт один
  query-параметр через запятую, и тест, что пункт «Композиции» виден и
  `ADMIN`, и `SUPER_ADMIN`
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  с сидом супер-админа
- Вход сидом: пункт «Композиции» открывает список. В сети
  `GET /compositions` без лишнего `status`/`tagIds`, если фильтры не
  трогали
- Создание композиции только с названием и автором: в сети `POST` без
  `status` (или с явным пониманием, что сервер ответил `DRAFT`); строка
  появляется в списке со статусом черновика
- Поиск по фрагменту названия находит строку; очистка поиска и поиск по
  фрагменту автора находит её снова
- Фильтр статуса «Черновик» оставляет эту строку; фильтр «Опубликована»
  её скрывает. Сброс статуса на «все» возвращает строку
- Навешивание тега при создании второй композиции или правка тегов на
  карточке первой: фильтр по этому тегу показывает нужную строку; в
  сети `tagIds` — одна строка. Фильтр двух тегов — OR (видна композиция
  с любым из них)
- Открытие карточки со списка: в сети ровно один `GET .../full`, нет
  повторного `GET /compositions`. Смена статуса на «Опубликована»:
  `PATCH` с `status: "PUBLISHED"`; после возврата к списку и фильтра
  «Опубликована» строка видна
- На карточке снятие последнего тега: в сети `PATCH` с `"tagIds":[]`;
  повторное чтение / возврат к списку показывает композицию без этого
  тега
- Удаление со списка: подтверждение говорит, что композиция исчезнет из
  списка и вернуть нельзя. После согласия в сети `DELETE` с `200` и
  `deletedAt`, строки в списке больше нет. Поиск по прежнему названию
  её не возвращает
- Выход, вход учёткой `ADMIN`: пункт «Композиции» есть, пункт «Теги»
  есть, пункт «Сотрудники» нет. С этой учётки создаётся ещё одна
  композиция-черновик, она видна в списке. Прямой адрес `/admins`
  по-прежнему показывает отказ

Композиции и теги, заведённые только для прохода, в конце имеет смысл
удалить (композиции — мягко с экрана, теги — с экрана тегов), если они
больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Создание, фильтры, публикация, снятие последнего тега
  с `[]`, удаление и вход под `ADMIN` — ручным проходом в браузере
  против запущенного `quizbeat-srv`, не только моком.
- В `npm run test` нет `.skip` на тесте стора про `tagIds` / `full`, на
  тесте карточки про ровно один `GET .../full`, на тесте удаления и на
  тесте пункта меню. Проверяется тем же прогоном.
