## Зачем

DoD этапа требует перетаскивание и проверку, что в `imageIds` уходит
полный текущий набор. Отдельная задача не ломает тест загрузки /
превью из задачи 2 и не смешивает его с удалением.

## Границы задачи

| Входит | Не входит |
|---|---|
| Перетаскивание элементов списка на карточке; после drop — `PATCH .../images/order` с полным `imageIds` в новом порядке | Загрузка файлов и первичное превью — [задача 2](./02-images-upload-and-list.md) |
| Обновление порядка на экране из ответа `200` или повторного `GET` | Удаление — [задача 4](./04-images-delete.md) |
| Тест: в теле уходит полный текущий набор id в новом порядке; пустой массив не шлётся | Фиксация имени DnD-библиотеки в декомпозиции; зависимость до реализации не добавлять |
| Показ `message` при `400` несовпадения набора | `noteIds` / заметки — [этап 7](../../03-technical-specification.md#этап-7--заметки-а-знали-ли-вы) |

## ⚠ Технические нюансы и ограничения

- `imageIds` — **полная замена**, не diff. После перестановки в запрос
  должны попасть все id текущего списка ровно по одному разу, в новом
  порядке. Пустой список на сервер не уходит (`@ArrayMinSize(1)`);
  на пустом UI drag не из чего начинать.
- Несовпадение с серверным набором — `400` с текстом
  `IMAGE_ID_SET_MISMATCH_MESSAGE`. Показать `message`, сессию не
  чистить. После чужого удаления/загрузки имеет смысл перечитать
  список перед повторным drop.
- Путь — `.../images/order`, литеральный сегмент. Не подставлять
  UUID картинки вместо `order`.
- Библиотека DnD — при реализации, по тайпингам установленной версии
  (правило 4). Имя пакета и пропы в этой задаче не фиксируются; DoD-
  тест смотрит на тело `imageIds`, не на API библиотеки. См.
  [README](./README.md#решения-по-открытым-вопросам-этапа).
- Общий файл — блок задачи 2. Вливать после 02, до 04 при конфликте.

## Объём работы

- На списке картинок — перетаскивание, меняющее визуальный порядок.
- По завершении жеста — вызов стора с полным массивом id в новом
  порядке; успех → актуальный порядок на экране (`order` с 0).
- Отказ API — на блоке, без очистки сессии.
- Тесты (мок `fetch` / стора):
  - после имитации смены порядка в сети уходит `PATCH` на
    `.../images/order` с телом `{ imageIds: [...] }`, длина и состав
    совпадают с текущим списком до запроса, порядок — новый;
  - пустой `imageIds` не отправляется;
  - `400` с сообщением несовпадения набора показывает `message`.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test` — в том числе
  тест полного `imageIds`, которого требует DoD этапа.
- `npm run lint` проходит.
- Ручной ориентир: после перетаскивания повторный `GET .../images`
  совпадает с экраном; полный проход — у
  [приёмки](./05-step6-acceptance.md).
