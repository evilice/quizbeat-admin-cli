## Зачем

DoD этапа начинается с черновика: без создания нечего фильтровать и
публиковать. Создание живёт на списке диалогом, а не отдельным
маршрутом — карточку заводит [задача 4](./04-composition-card.md) под
правку уже существующей строки и под блоки этапов 5–8. Удаление сюда не
входит: у него другое подтверждение и мягкий `DELETE` с `deletedAt`.
Пока нет списка из задачи 2, форму некуда поставить и после успеха
нечего обновлять.

## Границы задачи

| Входит | Не входит |
|---|---|
| Диалог создания на списке: название, автор, необязательный статус, необязательный набор тегов | Правка на карточке — [задача 4](./04-composition-card.md) |
| `POST /compositions`; пустые название или автор на сервер не уходят | Удаление — [задача 5](./05-delete-composition.md) |
| Выбор тегов через стор тегов этапа 3 | Отдельный маршрут `/compositions/new`. Создание — действие списка |
| `400` неизвестного тега на форме | Аудио и `GET /full` — [этап 5](../../03-technical-specification.md#этап-5--аудио-и-отрезки) / [этап 8](../../03-technical-specification.md#этап-8--сборка-карточки-композиции) |

## ⚠ Технические нюансы и ограничения

- Форма одна, вход — кнопка «Создать» на списке. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- Если человек оставил статус «черновик» / не менял его, поле `status` в
  JSON не уходит: дефолт `DRAFT` ставит сервис, не клиентский
  DTO-дефолт. Явный выбор «Опубликована» шлёт `status: "PUBLISHED"`.
- Набор тегов необязателен. Пустой выбор: поля `tagIds` в JSON нет
  (стор задачи 1 так и собирает). Непустой выбор — массив uuid в теле,
  не строка через запятую: строка — форма query списка, не тела.
- Пустое название или пустой автор на сервер не отправляются, на форме
  русское сообщение. Пробелы по краям клиент не обрезает.
- Неизвестный uuid тега — `400` и `message`
  `One or more tagIds do not reference an existing tag`. Форма показывает
  строку как есть, диалог остаётся открыт, список заново не
  запрашивается.
- Успех — `201`. Диалог закрывается, список перечитывается тем же
  запросом, который уже на экране (те же фильтры и страница). Ответ в
  таблицу в обход этого чтения не вставляется.
- Экран списка общий с задачами 4 и 5. Эта задача добавляет кнопку
  создания и не добавляет правку строки и удаление. При конфликте
  слияния она идёт сразу после задачи 2, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- На списке кнопка «Создать» открывает форму с пустыми названием и
  автором, статусом в положении «черновик» (поле в запрос не уйдёт) и
  пустым набором тегов. Подписи русские. Выбор тегов — из стора тегов.
- Отправка вызывает метод стора создания. Проверка до запроса: пустое
  название или пустой автор — русское сообщение, `fetch` не вызывается.
- При `201` диалог закрыт, список запрошен заново с текущими фильтрами
  и страницей. При `400` на форме видна строка сервера, диалог остаётся
  открыт.
- Тесты:
  - пустое название при заполненном авторе не вызывает `fetch`; то же
    для пустого автора;
  - создание без смены статуса не содержит ключ `status` в JSON;
  - создание с выбором «Опубликована» шлёт `status: "PUBLISHED"`;
  - создание без тегов не содержит ключ `tagIds`; с двумя тегами шлёт
    массив из двух uuid, не строку через запятую;
  - `201` закрывает диалог и вызывает повторное чтение списка;
  - `400` с текстом про неизвестный тег показывает эту строку и не
    запрашивает список заново.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят.
- В модуле формы создания нет вызова `GET /compositions/:id/full` и нет
  поля загрузки файла. Проверяется чтением формы.
