# Задача 2 — Список тегов и пункт меню

Этап: 3 — Справочник тегов.
Зависимости: [задача 1](./01-tags-store.md) (метод списка) и навигация
оболочки из [задачи 4 этапа 1](../step-1/04-role-menu.md). Тест пункта
меню в текущем виде — после
[списка сотрудников](../step-2/02-admins-list.md).
Ссылка на ТЗ: [раздел «Этап 3»](../../03-technical-specification.md#этап-3--справочник-тегов)
(список с поиском по названию и пагинацией).
Карта: строка `GET /tags` в [тегах](../../02-staff-api.md#4-теги).
Query и пагинация —
[`ListTagsQueryDto`](../../../../quizbeat-srv/src/tags/dto/list-tags-query.dto.ts)
и [`PaginationQueryDto`](../../../../quizbeat-srv/src/common/pagination/pagination-query.dto.ts),
порядок строк — `createdAt DESC` в
[`TagsService.list`](../../../../quizbeat-srv/src/tags/tags.service.ts).

## Зачем

Это первый экран контента и первый пункт меню, который виден обеим
ролям. Поиск по названию и пагинация входят в него сразу: отдельной
следующей задачей их не добавляют. Кнопки создания, правки и удаления
сюда не входят, иначе тест строки (код и оба названия, в том числе когда
поиск совпал только с одной локалью) смешается с диалогами, которых на
пустой странице быть не должно.

## Границы задачи

| Входит | Не входит |
|---|---|
| Пункт «Теги» в навигации и маршрут `/tags` со списком: поиск, пагинация, код и оба названия | `POST /tags` и `PATCH /tags/:id` — [задача 3](./03-tag-form.md) |
| Строка показывает код и названия `ru` и `en` из ответа сервера | Удаление — [задача 4](./04-delete-tag.md) |
| Правка теста меню: «Теги» видны и `ADMIN`, и `SUPER_ADMIN` | Скрытие пункта по роли. На `/tags` сервер не отвечает `403` из-за роли |
| | Фильтр тегов у композиций — [этап 4](../../03-technical-specification.md#этап-4--композиции) |

## ⚠ Технические нюансы и ограничения

- Пункт виден при любой роли staff, см.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
  Рядом остаётся пункт «Сотрудники», он по-прежнему только у
  `SUPER_ADMIN`. Обновление теста меню не возвращает утверждение
  «открытие `/admins` не вызывает `fetch`»: с этапа 2 этот маршрут
  ходит в API. Утверждение «`ADMIN` не видит пункт „Сотрудники“»
  остаётся. `.skip` на этом тесте — ослабление, а не правка стыка.
- Запрос идёт тем же клиентом, что и остальные защищённые вызовы, с
  access текущей сессии. На запрос без заголовка `Authorization` сервер
  отвечает `401`, и перехватчик этапа 1 открывает логин. Без сессии
  `/tags` по-прежнему ведёт на логин, как остальные маршруты оболочки.
- Поиск передаётся в стор как введённая строка. Пустая строка и пробелы
  параметр `search` не порождают — это собирает стор задачи 1. Смена
  строки поиска сбрасывает номер страницы на `1`. Иначе на экране
  останется `page=2` от прошлого поиска, и человек увидит пустую
  страницу при ненулевом `total` на первой.
- Название локали берётся по полю `locale`, не по позиции в
  `translations`. Сервер отдаёт оба перевода, даже если `ILIKE` совпал
  только с одним: прятать второе название на клиенте нельзя, поиск
  фильтрует теги, а не элементы массива. Код в условие поиска не входит.
  Строка, найденная по английскому названию, всё равно показывает
  русское.
- Порядок строк — порядок `items` в ответе. Свою сортировку клиент не
  добавляет: сервер уже отдаёт `createdAt DESC`.
- Код и названия рисуются текстом React. `dangerouslySetInnerHTML` для
  полей ответа не используется.
- Ошибка запроса показывает разобранное `message`, таблицы нет. Пустой
  `items` при `200` — отдельное состояние с русской подписью. Различие
  проверяется тестом: иначе отказ и пустой поиск выглядят одинаково.
  Отдельной ветки `403` по роли нет.
- Экран списка затем правят задачи 3 и 4. Эта задача заводит пункт,
  таблицу, поиск и пагинацию, без кнопок изменения данных. При конфликте
  слияния она вливается первой, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- В оболочке с сессией пункт «Теги» виден и `ADMIN`, и `SUPER_ADMIN` и
  ведёт на `/tags`.
- Маршрут `/tags` при живой сессии монтирует список и сразу вызывает
  метод стора из задачи 1. Без сессии путь по-прежнему ведёт на логин.
- На экране: поле поиска по названию и переключение страниц по `page` и
  `total`. Подписи русские. В строке видны код, название `ru` и название
  `en`.
- Обновить тест меню:
  - обе роли видят пункт «Теги», переход вызывает `GET /tags`;
  - `ADMIN` по-прежнему не видит пункт «Сотрудники»;
  - `SUPER_ADMIN` видит оба пункта;
  - открытие `/admins` под `ADMIN` по-прежнему получает отказ и не
    рисует список сотрудников.
- Отдельный тест экрана на моке `fetch`:
  - первая загрузка без текста поиска не содержит `search`;
  - ввод поиска даёт параметр `search` и сбрасывает страницу на `1`,
    если до этого была другая;
  - тег, у которого в массиве сначала `en`, показывает русское название
    в колонке `ru` и английское в колонке `en`;
  - пустой `200` и ответ с ошибкой (разобранное `message`) различаются:
    у ошибки нет пустого состояния списка, у пустой страницы нет текста
    отказа.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`, включая
  обновлённый тест меню. В нём нет `.skip`.
- `npm run lint` и `npm run build` проходят: маршрут `/tags` в сборке.
- В компоненте списка нет проверки роли, которая отменяет вызов стора.
  Проверяется чтением компонента.
