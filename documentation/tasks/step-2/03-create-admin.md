## Зачем

Вторая учётка нужна до экранов контента, и заводят её с этого списка,
отдельным маршрутом она не заводится. Форма отделена от смены роли и
сброса пароля: у создания другое тело (`password` и обязательная
`role`, успех `201`) и другая ошибка (`409` на занятый email). Пока нет
списка из задачи 2, кнопку некуда поставить и после успеха нечего
обновлять.

## Границы задачи

| Входит | Не входит |
|---|---|
| Диалог создания: email, пароль, роль; `POST /admins`; после `201` список перечитывается | Правка уже существующей строки — [задача 4](./04-role-and-activity.md) |
| Пароль короче 8 символов и пустой email на сервер не уходят | Сброс пароля и поле `newPassword` — [задача 5](./05-reset-password.md). Смена своего пароля остаётся в шапке этапа 1 |
| `409` с текстом сервера на форме | Запись роли новой учётки в access текущей сессии. Создание чужого сотрудника токены не меняет |

## ⚠ Технические нюансы и ограничения

- В селекте роль по умолчанию — `ADMIN`, и в теле она есть всегда.
  Без `role` сервер ответит `400`: у `CreateAdminDto` своего значения
  по умолчанию нет. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- Пароль короче 8 символов на сервер не отправляется. Порог — 8, как
  `MIN_PASSWORD_LENGTH`, не свой набор правил. Пустой email тоже не
  отправляется. Если сервер всё же ответил `400` и `message` массивом,
  форма показывает весь список через уже существующий разбор ошибки.
- Занятый email — `409` и `message`
  `Admin with this email already exists`. Сервер сравнивает
  нормализованный адрес (`trim` и нижний регистр), поэтому повтор с
  другим регистром даёт тот же `409`. Форма показывает эту строку как
  есть и не очищает поля так, будто создание прошло.
- Успех — `201`, пароля в теле нет. Пароль не пишется ни в стор, ни в
  `localStorage`. Список перечитывается тем же запросом, который уже
  на экране (те же фильтры и та же страница). Если фильтр скрывает новую
  роль, строки в таблице может не быть: так и должен работать фильтр.
  Ответ `201` в таблицу в обход этого чтения не вставляется.
- Созданная учётка активна: сервер сам ставит `isActive: true`. Форма
  это поле не шлёт.
- Экран списка общий с задачами 4 и 5. Эта задача добавляет кнопку и
  диалог создания и не добавляет действия строки. При конфликте слияния
  она идёт сразу после задачи 2, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- На списке кнопка «Создать» открывает форму: email, пароль, роль.
  Подписи русские. Роль по умолчанию — `ADMIN`, второй вариант —
  `SUPER_ADMIN`.
- Отправка вызывает метод стора с `{ email, password, role }`.
  Проверка до запроса: пустой email или пароль короче 8 — русское
  сообщение, `fetch` не вызывается.
- При `201` диалог закрыт, список запрошен заново с текущими фильтрами.
  При `409` на форме видна строка `Admin with this email already exists`,
  диалог остаётся открыт. Любой другой отказ показывает разобранное
  `message`.
- Тесты:
  - пароль из 7 символов не вызывает `fetch`;
  - отправка с ролью по умолчанию шлёт `role: 'ADMIN'`, email и пароль
    и не шлёт `isActive`;
  - `201` закрывает диалог и вызывает повторное чтение списка;
  - `409` с текстом про занятый email показывает эту строку и не
    запрашивает список заново.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят.
- В модуле формы создания есть поле `password` и нет `newPassword` и
  `currentPassword`. Проверяется чтением формы.
