# Условия приёмки против живого сервера

Общее для всех задач «Приёмка этапа N» (`step-1/06` … `step-8/02`), которые
проходятся ручным проходом против запущенного `quizbeat-srv`. Вынесено
сюда одним местом по правилу
[task-writing-guidelines.md](./task-writing-guidelines.md#3-сквозные-правила-читаемости)
(«нюанс, актуальный для нескольких задач сразу, дублируется короткой
перекрёстной ссылкой») — эти два условия меняются разом при правке
окружения (переименование переменной сида, смена порта, схемы
сидирования), и синхронно править восемь копий дороже, чем сослаться на
одну.

## Сид `SUPER_ADMIN`

Сид `SUPER_ADMIN` создаётся при старте `quizbeat-srv`, только если
`NODE_ENV` не `test` и в env сервера заданы `SUPER_ADMIN_EMAIL` и
`SUPER_ADMIN_PASSWORD`. Приёмка против сервера с `NODE_ENV=test` логином
сида не подтверждается: автосид там выключен. Пароли — сида и любых
учёток, заведённых в проходе, — в этот репозиторий не копируются.

Начиная с [этапа 3](../03-technical-specification.md#этап-3--справочник-тегов),
где приёмка проходит под обеими ролями: учётка `ADMIN` для этого —
та, что заведена с экрана сотрудников на
[этапе 2](../03-technical-specification.md#этап-2--сотрудники), а не
запись, добавленная в БД в обход клиента. Иначе создание сотрудника
остаётся непроверенным.

## Порт dev-сервера

Клиент открывается на `http://localhost:5173`. Если порт занят,
`strictPort` (заведён [задачей 1 этапа 0](./step-0/01-project-scaffold.md))
роняет dev-сервер вместо того, чтобы молча переехать на другой порт.
Переносить порт нельзя: этот адрес прописан в `CORS_ORIGIN_ADMIN`
бэкенда — смена порта без правки env сервера выглядит как «API не
отвечает», хотя на самом деле падает CORS.
