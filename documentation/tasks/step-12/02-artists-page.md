# Задача 2 — Страница «Исполнители»

Этап: 12 — Исполнители вместо автора.
Зависимости: [задача 1](./01-composition-artists-field.md) (стор `artists`);
серверный этап 17,
[задача 2](../../../../quizbeat-srv/documentation/tasks/step-17/02-staff-artists-and-compositions.md)
(`PATCH`/`DELETE /artists/:id`); образец — модуль тегов
([этап 3](../step-3/README.md)).
Ссылка на ТЗ: [раздел «Этап 12»](../../03-technical-specification.md#этап-12--исполнители-вместо-автора).
Карта: раздел «Исполнители» в
[staff-api.md](https://github.com/evilice/quizbeat-docs/blob/main/api/staff-api.md).

**Задачу можно отложить:** этап и серверная задача 4 закрываются без неё
(исполнителя создают прямо в форме композиции). Пока страницы нет,
составные значения из старого `author` исправить нельзя.

## Зачем

Миграция сервера переносит значения `author` в справочник как есть, в том
числе составные вроде «Eminem, Rihanna» или «Earth, Wind & Fire». Их нужно
переименовать и при необходимости заменить в композициях на нескольких
исполнителей. Для этого нужен экран справочника: список, переименование,
удаление неиспользуемых.

## Границы задачи

| Входит | Не входит |
|---|---|
| Страница `/artists` и пункт меню «Исполнители» для любого staff | Слияние двух исполнителей, массовые операции |
| Список с поиском и пагинацией, создание, переименование (`PATCH`) | Фильтр композиций по исполнителю, список композиций исполнителя |
| Удаление неиспользуемого с подтверждением; `409` — «используется в N композициях» | Изменение сервера |

## ⚠ Технические нюансы и ограничения

- **Образец — `TagsPage`** (стор, таблица, форма в диалоге, диалог
  удаления, пагинация). Копировать структуру, не дублировать общие куски:
  если у тегов и исполнителей совпадает каркас таблицы или диалога
  подтверждения, выносить в `shared`, а не писать вторую копию.
- **`409` при удалении** — исполнитель используется; сервер отдаёт число
  композиций в `details`. Показать одной строкой в самом диалоге, не очищать
  сессию. `409` при создании и переименовании — имя занято (без учёта
  регистра и пробелов по краям).
- **Переименование видно сразу во всех композициях,** об этом предупреждает
  подпись формы: «Имя изменится у всех композиций».
- **Без роли:** доступно любому staff (как теги), пункт меню без `role`.
- **Файлы, которые трогает и [задача 1](./01-composition-artists-field.md):**
  `root-store.ts` (стор уже добавлен там), `routes.tsx`, `PagesMenu.tsx`
  правит только эта задача.

- Документация: ТЗ, [status.md](../status.md), `README.md` этапа.

## План реализации

1. **Разведка (правило 1).** Прочитать `modules/tags/` целиком, `routes.tsx`,
   `PagesMenu.tsx`; сверить формы ответов с `staff-api.md` и DTO сервера.
2. **Тесты сначала (на моке `fetch`).** Стор: `update` шлёт `PATCH` с
   `{ name }`, `remove` — `DELETE`; `409` разобран. Страница: поиск
   перезапрашивает список, создание и переименование открывают диалог,
   удаление требует подтверждения, `409` показывает число композиций.
3. **Расширить стор, страница, формы.** Выносить общее с тегами в `shared`
   только там, где совпадение полное.
4. **Меню и маршрут.** `{ label: 'Исполнители', to: '/artists' }`.
5. **Документация, проверки:** `npm run test`, `lint`, `build`;
   `/code-review` (правило 7) и Impact; без подтверждения не коммитить.

## Критерии готовности

- `npm run test`, `npm run lint`, `npm run build` проходят.
- Тесты на моке: переименование шлёт `PATCH`; `409` на дубль имени и на
  удаление используемого разобраны; удаление требует подтверждения.
- Пункт «Исполнители» виден и `ADMIN`, и `SUPER_ADMIN`.
- Ручной проход на живом сервере — в [задаче 3](./03-step12-acceptance.md).
