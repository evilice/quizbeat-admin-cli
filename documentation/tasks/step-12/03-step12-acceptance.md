# Задача 3 — Приёмка этапа 12

Этап: 12 — Исполнители вместо автора.
Зависимости: [задача 1](./01-composition-artists-field.md) (и
[задача 2](./02-artists-page.md), если сделана); серверный этап 17,
[задачи 1–3](../../../../quizbeat-srv/documentation/tasks/step-17/README.md),
особенно
[задача 2](../../../../quizbeat-srv/documentation/tasks/step-17/02-staff-artists-and-compositions.md),
в `main`.
Ссылка на ТЗ: [DoD раздела «Этап 12»](../../03-technical-specification.md#этап-12--исполнители-вместо-автора).

Условия приёмки (сид, порт, образ сервера) — [acceptance-preconditions.md](../acceptance-preconditions.md).

## Зачем

Сверка клиента с реальным ответом сервера и проверка миграции данных глазами
пользователя. После этой приёмки серверная задача 4 удаляет колонку `author`,
поэтому пройти её нужно до неё и на данных с реальными значениями `author`.
Новой функциональности нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| `lint`, `test`, `build` и ручной проход против `quizbeat-srv` с этапом 17 (задачи 1–3) | Игровой клиент |
| Исправление стыка, если форма ответа расходится с сервером | Новые поля и экраны |

## ⚠ Технические нюансы и ограничения

- **Проход на копии данных с реальными значениями `author`,** не на пустой
  БД: иначе перенос и составные значения не проверяются.
- **Образ `quizbeat-app` должен быть собран из `main` с этапом 17** (см.
  [acceptance-preconditions.md](../acceptance-preconditions.md#образ-сервера)),
  иначе проход идёт против старого `author`. Записать коммит, из которого
  собран образ.
- **Пока серверная задача 4 не выполнена, колонка `author` ещё есть,** но
  staff-API её не принимает и не отдаёт; сервер выводит её из связей. В
  запросах клиента `author` быть не должно ни в одном сценарии.
- **Порядок проверяется по телу запроса,** а не только по экрану: в
  `POST`/`PATCH` массив `artistIds` идёт в порядке чипов. В `PATCH` без
  изменения поля `artistIds` отсутствует, при снятии всех — `[]`.
- **Заголовок карточки без исполнителей — только название,** без второго
  тире. Подпись «—» проверяется в списке и диалоге удаления; поле формы без
  исполнителей — без чипов.
- Данные прохода (исполнители, композиции) в конце удаляются; перенесённых
  из старых значений не трогать. Удалять можно только неиспользуемых
  исполнителей; используемого сервер не даст.

## Объём работы

Ручной проход под `SUPER_ADMIN`:

1. **Список и поиск.** Список композиций показывает исполнителей из
   перенесённых значений `author`; у композиции без исполнителей — «—».
   Поиск находит и по названию, и по имени исполнителя. Заголовок колонки —
   «Исполнители».
2. **Карточка.** У композиции с несколькими исполнителями заголовок
   «Название — A, B»; у композиции без исполнителей — только название.
   Поле формы показывает чипы в сохранённом порядке.
3. **Создание без исполнителей.** Черновик и публикация проходят; в
   `POST /compositions` нет `artistIds`, в ответе `artists: []`.
4. **Создание с исполнителями.** Двое, один создан в поле «на лету»;
   `artistIds` в порядке выбора; после F5 и в карточке порядок тот же.
5. **Правка.** Смена порядка стрелками отправляет полный упорядоченный
   `artistIds`; снятие всех — `artistIds: []`; сохранение без изменения
   поля не отправляет `artistIds`.
6. **Дубль имени (`409`).** В двух вкладках открыть форму композиции, в
   обеих найти одно и то же несуществующее имя; в первой создать
   исполнителя, во второй нажать «Создать «…»» на устаревшей выдаче.
   Вторая вкладка не показывает ошибку: повторный поиск находит запись по
   точному имени, и она выбирается.
7. **Диалог удаления композиции** показывает подпись исполнителей или «—».

Если [задача 2](./02-artists-page.md) сделана:

8. **Страница «Исполнители».** Поиск, пагинация, создание; переименование
   составного значения (например, «Eminem, Rihanna») видно в связанных
   композициях после перезагрузки; «Earth, Wind & Fire» переименовывается как
   одно имя, без разбора; удаление неиспользуемого — `204`; удаление
   используемого — `409` с числом композиций в диалоге; прямое открытие
   `/artists` под `ADMIN`.
9. **Меню.** «Исполнители» видно и `ADMIN`, и `SUPER_ADMIN`.

Под `ADMIN`: тот же сценарий создания композиции с исполнителями; пунктов
«Сотрудники» и «Хранилище» нет. Результат записать в
[status.md](../status.md).

## Критерии готовности

- `npm run lint`, `npm run test`, `npm run build` без ошибок.
- Сценарий выше пройден на живом сервере; запросы в вкладке сети совпадают
  с картой `staff-api.md`: `artistIds` в нужном порядке, при снятии — `[]`,
  без изменения — поля нет, `author` нет ни в одном запросе.
- В интерфейсе нет слова «автор»; пустой список исполнителей — «—»; заголовок
  карточки без исполнителей не содержит второго тире.
- Если задача 2 сделана: переименование и удаление исполнителей проверены,
  `409` показывает число композиций.
- Этап 12 отмечен в [status.md](../status.md); серверная задача 4 может
  стартовать.
