# Задача 5 — Приёмка этапа 3

Этап: 3 — Справочник тегов.
Зависимости: [задача 3](./03-tag-form.md) и
[задача 4](./04-delete-tag.md) (и транзитивно список из
[задачи 2](./02-tags-list.md)).
Ссылка на ТЗ: [DoD раздела «Этап 3»](../../03-technical-specification.md#этап-3--справочник-тегов).

## Зачем

Задачи 1–4 по отдельности закрывают форму запроса и отказы на моке.
DoD этапа — другой контур: на живом `quizbeat-srv` тег заводится с
обоими названиями, находится поиском, меняет название и удаляется.
Запрос без одного перевода не уходит. Стык легко остаётся зелёным в
тестах, когда правка ушла одной локалью или поиск сравнивает код.
Новой функциональности здесь нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| Прогон `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` | Карточки композиций и проверка, что композиция осталась без удалённого тега — [этап 4](../../03-technical-specification.md#этап-4--композиции). Текст подтверждения это последствие уже называет |
| Исправление стыка, если задачи 1–4 не складываются в DoD: в `PATCH` одна локаль, поиск фильтрует по коду на клиенте, пустой `204` показан как ошибка | Подмена порта 5173 или базового URL. Порт зафиксирован в [задаче 1 этапа 0](../step-0/01-project-scaffold.md) |
| Проход и под `ADMIN`, и под `SUPER_ADMIN`: пункт «Теги» есть у обеих ролей | Новый раздел сотрудников. Видимость пункта «Сотрудники» остаётся как после этапа 2 |

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN`, учётки `ADMIN` и порта dev-сервера — общие
  для всех этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
- Поиск на сервере — подстрока названия в любой локали, без учёта
  регистра. Код в условие не входит. Проход ищет тег по фрагменту
  русского названия и отдельно по фрагменту английского; оба раза в
  строке видны и код, и оба названия. Поиск по самому коду в DoD не
  входит: пустая страница на такой строке — ожидаемый ответ сервера,
  если этот код не встретился внутри названия.
- Правка в сети — `PATCH` с `code` и двумя элементами `translations`, у
  каждого поле `name`. Тело с одной локалью или с полем `text` DoD не
  закрывает, даже если список после этого выглядит правильным.
- Удаление в сети — `DELETE` и ответ `204` без тела. Строка пропадает
  после повторного чтения списка. Восстановления на экране нет.
- `npm run test` гоняется один раз по всему `src/`. В выводе должны быть
  тест формы (запрос без одного перевода не уходит) и тест меню (пункт
  «Теги» виден обеим ролям, пункт «Сотрудники» — только `SUPER_ADMIN`).
  Отдельный прогон «только приёмочных» DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–4. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест, что пустое название не вызывает
  `fetch`, и тест, что пункт «Теги» виден и `ADMIN`, и `SUPER_ADMIN`
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  с сидом супер-админа
- Вход сидом: пункт «Теги» открывает список. В сети `GET /tags`
- Создание тега с кодом и обоими названиями: строка появляется в списке,
  в ней видны код, русское и английское названия. В теле запроса поле
  перевода — `name`, локали две
- Поиск по фрагменту русского названия находит эту строку, и в ней
  по-прежнему видно английское название. Очистка поиска и поиск по
  фрагменту английского названия находит её снова
- Правка русского названия: в сети `PATCH` с обеими локалями; после
  повторного чтения в строке новое русское название и прежнее
  английское
- Повторное создание с тем же кодом показывает
  `Tag with this code already exists`, диалог остаётся, второй строки с
  этим кодом в списке нет
- Очистка одного названия в форме и попытка сохранения: запроса в сети
  нет
- Удаление: подтверждение говорит, что тег удаляется безвозвратно,
  композиции теряют связь и сами не удаляются. После согласия в сети
  `DELETE` с `204`, строки в списке больше нет. Поиск по прежнему
  названию её не возвращает
- Выход, вход учёткой `ADMIN`: пункт «Теги» есть, пункт «Сотрудники»
  нет. С этой учётки создаётся второй тег, он виден в списке. Прямой
  адрес `/admins` по-прежнему показывает отказ, без таблицы сотрудников

Теги, заведённые для прохода, в конце имеет смысл удалить, если они
больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Создание, поиск, правка, отказ по занятому коду,
  запрет запроса без перевода, удаление и вход под `ADMIN` — ручным
  проходом в браузере против запущенного `quizbeat-srv`, не только моком.
- В `npm run test` нет `.skip` на тесте формы, на тесте удаления и на
  тесте пункта меню. Проверяется тем же прогоном.
