# Задача 2 — Список сотрудников вместо заглушки

Этап: 2 — Сотрудники.
Зависимости: [задача 1](./01-admins-store.md) (метод списка) и маршрут
`/admins` из [задачи 4 этапа 1](../step-1/04-role-menu.md).
Ссылка на ТЗ: [раздел «Этап 2»](../../03-technical-specification.md#этап-2--сотрудники)
(список, фильтры, деактивированные видны, прямой заход `ADMIN` получает
`403` и не рисует список).
Карта: строка `GET /admins` в
[сотрудниках](../../02-staff-api.md#3-сотрудники).
Query и пагинация —
[`ListAdminsQueryDto`](../../../../quizbeat-srv/src/admin/dto/list-admins-query.dto.ts),
порядок строк — `createdAt DESC` в
[`AdminsService.list`](../../../../quizbeat-srv/src/admin/admins.service.ts).

## Зачем

Заглушка этапа 1 специально не ходила в сеть, чтобы отказ сервера было
не с чем спутать. Этот экран — первое место, где `ADMIN` на `/admins`
получает настоящий `403` и где супер-админ видит деактивированных вместе
с активными. Кнопки создания и кнопки строки сюда не входят: иначе тест
«при отказе списка нет» смешается с диалогами, которых при `403` быть
не должно.

## Границы задачи

| Входит | Не входит |
|---|---|
| Замена заглушки `/admins` списком: поиск по email, фильтр роли, фильтр активности, пагинация | `POST /admins` — [задача 3](./03-create-admin.md) |
| Строка показывает email, роль и активность из ответа сервера, в том числе при `isActive: false` | Смена роли, деактивация, активация — [задача 4](./04-role-and-activity.md). Сброс пароля — [задача 5](./05-reset-password.md) |
| `403`: на экране `message` сервера, таблицы нет | Второй пункт меню. Видимость «Сотрудники» остаётся правилом этапа 1: пункт виден только `SUPER_ADMIN` |
| Правка теста этапа 1, который ждал заглушку без `fetch` | Отказ, нарисованный клиентом до запроса. Прямой заход и под `ADMIN` шлёт `GET /admins` |

## ⚠ Технические нюансы и ограничения

- Запрос идёт тем же клиентом, что и остальные защищённые вызовы, с
  access текущей сессии. На запрос без заголовка `Authorization` сервер
  отвечает `401`, и перехватчик этапа 1 открывает логин. DoD «прямой URL
  показывает отказ» тогда не выполнен: на экране нет `403`.
- При `403` нет ни пустой таблицы, ни надписи «никого не найдено».
  Пустой `items` при `200` — отдельное состояние с русской подписью.
  Различие проверяется тестом: иначе отказ и пустой поиск выглядят
  одинаково.
- Фильтр активности — три состояния из
  [решений этапа](./README.md#решения-по-открытым-вопросам-этапа).
  Первая загрузка не передаёт `isActive`. Смена поиска, роли или
  активности сбрасывает номер страницы на `1`. Иначе на экране останется
  `page=2` от прошлого фильтра, и человек увидит пустую страницу при
  ненулевом `total` на первой.
- Порядок строк — порядок `items` в ответе. Свою сортировку клиент не
  добавляет: сервер уже отдаёт `createdAt DESC`.
- Email, роль и статус рисуются текстом React. Для `ADMIN` и
  `SUPER_ADMIN` на экране — русские подписи, в запрос уходят сами эти
  значения. `dangerouslySetInnerHTML` для полей ответа не используется.
- Тест этапа 1 на заглушку проверяет, что открытие `/admins` не вызывает
  `fetch` и показывает пометку следующего этапа. Здесь маршрут начинает
  запрашивать список, и тест обновляется под новое поведение.
  Утверждение «`ADMIN` не видит пункт меню» остаётся. `.skip` на этом
  тесте — ослабление, а не правка стыка.
- Экран списка затем правят задачи 3, 4 и 5. Эта задача заводит таблицу,
  фильтры и пагинацию, без кнопок изменения данных. При конфликте слияния
  она вливается первой, см. [README](./README.md#почему-такой-порядок).

## Объём работы

- Маршрут `/admins` при живой сессии монтирует список и сразу вызывает
  метод стора из задачи 1. Без сессии путь по-прежнему ведёт на логин.
- На экране: поле поиска по email, выбор роли (все / `ADMIN` /
  `SUPER_ADMIN`), выбор активности (все / только активные / только
  неактивные), переключение страниц по `page` и `total`. Подписи
  русские.
- В строке видны email, роль и состояние «активен» или «неактивен».
  В списке по умолчанию деактивированный сотрудник виден.
- При `403` виден `message` ответа, таблицы и пустого состояния нет.
  При `200` с пустым `items` есть пустое состояние и нет сообщения
  отказа.
- Обновить тест пункта меню этапа 1:
  - `SUPER_ADMIN` по-прежнему видит пункт, переход на `/admins` вызывает
    `GET /admins`;
  - `ADMIN` пункт не видит;
  - открытие `/admins` под `ADMIN` вызывает один `GET /admins` и
    показывает `message` отказа, без строк списка;
  - id оболочки по-прежнему равен `sub` токена.
- Отдельный тест экрана на моке `fetch`:
  - первая загрузка не содержит `isActive` в query, строка с
    `isActive: false` видна;
  - выбор «только неактивные» даёт `isActive=false` и сбрасывает
    страницу на `1`, если до этого была другая;
  - пустой `200` и `403` различаются, как в объёме выше.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`, включая
  обновлённый тест пункта меню. В нём нет `.skip`.
- `npm run lint` и `npm run build` проходят: маршрут `/admins` в сборке
  ведёт на список, не на заглушку.
- В компоненте списка нет второго разбора JWT и нет выхода по роли до
  вызова стора. Проверяется чтением компонента.
