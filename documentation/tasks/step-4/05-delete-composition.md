# Задача 5 — Удаление композиции

Этап: 4 — Композиции.
Зависимости: [задача 2](./02-compositions-list.md) (строка списка) и
метод удаления из [задачи 1](./01-compositions-store.md).
Ссылка на ТЗ: [раздел «Этап 4»](../../03-technical-specification.md#этап-4--композиции)
(`DELETE /compositions/:id` — мягкое удаление, `200` с `deletedAt`, с
подтверждением; вернуть нельзя).
Карта: строка `DELETE /compositions/:id` в
[композициях](../../02-staff-api.md#5-композиции).
Сервис —
[`CompositionsService.remove`](../../../../quizbeat-srv/src/compositions/compositions.service.ts).

## Зачем

Удаление композиции необратимо из интерфейса и легко перепутать с
деактивацией сотрудника (`DELETE` с `isActive: false` в ответе, строка
остаётся в списке при фильтре «все») или с жёстким удалением тега
(`204` без тела). Здесь успех — `200` с `deletedAt`, после повторного
чтения строки в списке нет, восстановления нет. Подтверждение — место,
где человек это видит до запроса. Задача опирается на строку из задачи
2: без названия и автора в тексте нечего назвать.

## Границы задачи

| Входит | Не входит |
|---|---|
| Удаление строки списка через `DELETE /compositions/:id` с подтверждением | Создание — [задача 3](./03-create-composition.md). Карточка — [задача 4](./04-composition-card.md) |
| Текст подтверждения: исчезнет из списка, вернуть из интерфейса нельзя | Кнопка удаления на карточке. DoD этапа закрывается со списка |
| После `200` список перечитывается, строки больше нет | Восстановление удалённой композиции. Такого действия на сервере нет — [вне плана](../../03-technical-specification.md#4-вне-текущего-плана) |
| | Каскад по аудио/картинкам/заметкам на экране. Этих блоков ещё нет |

## ⚠ Технические нюансы и ограничения

- Удаление — `DELETE`, успех `200` с телом и заполненным `deletedAt`.
  Метод стора из задачи 1 уже читает JSON. Нельзя обрабатывать ответ как
  пустой `204` тегов: тело есть, `deletedAt` не `null`. Связки с тегами
  сервер не трогает; в списке строка пропадает из-за фильтра
  `deletedAt IS NULL`, не из-за каскада.
- Текст подтверждения по-русски говорит: композиция исчезнет из списка;
  вернуть её из интерфейса нельзя; отдельного восстановления на сервере
  нет. Формулировок «деактивировать» и «безвозвратно стереть файлы» нет —
  мягкое удаление строки БД пользователю объясняется через исчезновение
  из списка. Отмена не вызывает `fetch`. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- В подтверждении видны название и автор удаляемой строки.
- `404` (уже удалена или неверный id) показывает `message` и
  перечитывает список. `400` про теги на этом пути сервер не отвечает.
- После `200` список перечитывается с текущими фильтрами и страницей.
  Строка до ответа сервера из таблицы не исчезает. Ответ удаления в
  таблицу не подмешивается: после soft-delete его не должно быть в
  следующем `GET`.
- Экран списка общий с задачами 3 и 4. Эта задача добавляет на строку
  удаление. При конфликте слияния она идёт после задачи 4, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- На строке действие «Удалить» открывает подтверждение с названием и
  автором. Подписи русские. В тексте есть последствия из нюанса выше.
- Отмена закрывает подтверждение и не вызывает `fetch`. Согласие
  вызывает `DELETE` с id строки.
- При успехе список запрашивается заново с текущими фильтрами и
  страницей, подтверждение закрыто. При `404` на экране виден
  `message`, список запрашивается заново.
- Тесты:
  - отмена не вызывает `fetch`, строка остаётся;
  - согласие шлёт `DELETE` на путь с uuid этой строки;
  - ответ `200` с `deletedAt` убирает подтверждение и вызывает
    повторное чтение списка;
  - до ответа сервера строка в таблице на месте;
  - обработчик не ожидает пустой `204` и не зовёт `PATCH` с признаком
    активности;
  - `404` показывает `message` и запрашивает список заново.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят.
- В обработчике удаления нет чтения ответа как пустого `204` и нет
  `PATCH` вместо `DELETE`. Проверяется чтением обработчика.
