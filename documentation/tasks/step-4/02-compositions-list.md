# Задача 2 — Список композиций и пункт меню

Этап: 4 — Композиции.
Зависимости: [задача 1](./01-compositions-store.md) (метод списка),
навигация оболочки из [задачи 4 этапа 1](../step-1/04-role-menu.md)
и стор тегов из [задачи 1 этапа 3](../step-3/01-tags-store.md) (фильтр
тегов). Тест пункта меню в текущем виде — после
[списка тегов](../step-3/02-tags-list.md).
Ссылка на ТЗ: [раздел «Этап 4»](../../03-technical-specification.md#этап-4--композиции)
(список с поиском, фильтром статуса и тегов, пагинацией).
Карта: строка `GET /compositions` в
[композициях](../../02-staff-api.md#5-композиции).
Query —
[`ListCompositionsQueryDto`](../../../../quizbeat-srv/src/compositions/dto/list-compositions-query.dto.ts),
порядок строк — `createdAt DESC` в
[`CompositionsService.list`](../../../../quizbeat-srv/src/compositions/compositions.service.ts).

## Зачем

Это первый экран композиций и пункт меню рядом с «Тегами». Поиск,
фильтр статуса, фильтр тегов и пагинация входят сразу: отдельной
следующей задачей их не добавляют. Кнопки создания, правки и удаления
сюда не входят, иначе тест «query собрал `tagIds` одной строкой» и
тест строки (название, автор, статус, чипы тегов) смешаются с
диалогами и карточкой.

## Границы задачи

| Входит | Не входит |
|---|---|
| Пункт «Композиции» в навигации и маршрут `/compositions` со списком: поиск, фильтр статуса, фильтр тегов, пагинация | `POST /compositions` — [задача 3](./03-create-composition.md) |
| Строка показывает название, автора, статус и теги из ответа | Маршрут `/compositions/:id` и `PATCH` — [задача 4](./04-composition-card.md) |
| Фильтр тегов читает справочник через стор тегов этапа 3 | Удаление — [задача 5](./05-delete-composition.md) |
| Правка теста меню: «Композиции» видны и `ADMIN`, и `SUPER_ADMIN`; видимость «Теги» и «Сотрудники» не откатывается | Скрытие пункта по роли. На `/compositions` сервер не отвечает `403` из-за роли |
| | Аудио, отрезки — [этап 5](../../03-technical-specification.md#этап-5--аудио-и-отрезки). `GET /compositions/:id/full` принадлежит карточке — [задача 4](./04-composition-card.md), не списку |

## ⚠ Технические нюансы и ограничения

- Пункт виден при любой роли staff, см.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
  Рядом остаются «Теги» (обе роли) и «Сотрудники» (только
  `SUPER_ADMIN`). Обновление теста меню не возвращает утверждение
  «открытие `/admins` не вызывает `fetch`» и не убирает пункт «Теги» у
  `ADMIN`. `.skip` на этом тесте — ослабление, а не правка стыка.
- Запрос идёт тем же клиентом, что и остальные защищённые вызовы, с
  access текущей сессии. Без сессии `/compositions` по-прежнему ведёт на
  логин.
- Поиск, статус и набор тегов передаются в стор как значения экрана.
  Пустой поиск и пробелы параметр `search` не порождают; «все» статусы —
  параметра `status` нет; пустой выбор тегов — параметра `tagIds` нет.
  Склейку `tagIds` в одну строку делает стор задачи 1, не экран. Смена
  любого фильтра сбрасывает номер страницы на `1`.
- Фильтр тегов не заводит второй `GET /tags`: вызывает метод списка стора
  тегов этапа 3. Непагинированного списка на сервере нет — `limit`
  максимум 100. Семантика нескольких выбранных тегов — OR на сервере;
  клиент это не пересчитывает.
- В ответе у каждой композиции `tags` — массив
  [`TagResponseDto`](../../../../quizbeat-srv/src/tags/dto/tag-response.dto.ts),
  не массив uuid. Название в чипе — по полю `locale` (на экране
  достаточно показать `ru`, если есть). Порядок строк — порядок `items`
  в ответе; свою сортировку клиент не добавляет.
- Подписи статуса на экране русские («Черновик», «Опубликована»); в
  query уходят `DRAFT` / `PUBLISHED`. Название, автор и тексты тегов
  рисуются текстом React. `dangerouslySetInnerHTML` не используется.
- Ошибка запроса показывает разобранное `message`, таблицы нет. Пустой
  `items` при `200` — отдельное состояние с русской подписью. Отдельной
  ветки `403` по роли нет.
- Экран списка затем правят задачи 3, 4 и 5. Эта задача заводит пункт,
  таблицу, поиск, фильтры и пагинацию, без кнопок изменения данных. При
  конфликте слияния она вливается первой, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- В оболочке с сессией пункт «Композиции» виден и `ADMIN`, и
  `SUPER_ADMIN` и ведёт на `/compositions`.
- Маршрут `/compositions` при живой сессии монтирует список и сразу
  вызывает метод стора из задачи 1. Без сессии путь по-прежнему ведёт на
  логин.
- На экране: поле поиска по названию/автору, фильтр статуса (все /
  черновик / опубликована), мультивыбор тегов из стора тегов,
  переключение страниц по `page` и `total`. Подписи русские. В строке
  видны название, автор, статус и теги ответа.
- Обновить тест меню:
  - обе роли видят пункт «Композиции», переход вызывает
    `GET /compositions`;
  - обе роли по-прежнему видят пункт «Теги»;
  - `ADMIN` по-прежнему не видит пункт «Сотрудники»;
  - `SUPER_ADMIN` видит «Сотрудники», «Теги» и «Композиции»;
  - открытие `/admins` под `ADMIN` по-прежнему получает отказ и не
    рисует список сотрудников.
- Отдельный тест экрана на моке `fetch`:
  - первая загрузка без поиска, статуса и тегов не содержит `search`,
    `status`, `tagIds`;
  - выбор двух тегов даёт один параметр `tagIds` со значением через
    запятую и сбрасывает страницу на `1`, если до этого была другая;
  - выбор статуса `DRAFT` даёт `status=DRAFT`; состояние «все» параметра
    `status` не содержит;
  - ввод поиска даёт параметр `search` и сбрасывает страницу на `1`;
  - строка с тегом, у которого в массиве сначала `en`, показывает
    русское название в чипе, если локаль `ru` есть;
  - пустой `200` и ответ с ошибкой (разобранное `message`) различаются.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`, включая
  обновлённый тест меню. В нём нет `.skip`.
- `npm run lint` и `npm run build` проходят: маршрут `/compositions` в
  сборке.
- В компоненте списка нет проверки роли, которая отменяет вызов стора, и
  нет собственного `fetch` на `/tags` в обход стора тегов. Проверяется
  чтением компонента.
