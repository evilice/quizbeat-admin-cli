## Зачем

Агрегат карточки должен ходить через один метод стора: один путь,
разбор `null` у аудио-полей и `404` без побочных эффектов на сессию.
Пока контракт не зафиксирован тестом, экран легко вызовет
`GET .../audio` при `null` URL или примет мягко удалённую композицию
за пустую карточку. Экран и правило мутаций в эту задачу не входят:
сеть проверяется моком `fetch`.

## ⚠ Технические нюансы и ограничения

- При отсутствии трека сервер отдаёт
  `originalAudioUrl: null` и `originalAudioDurationSec: null`, а не
  опускает поля. `null` — нормальное состояние свежесозданной
  композиции (`getFull` **не** зовёт `getAudioUrl()`, тот бросил бы
  `404`). Клиентский метод при `null` не подставляет пустую строку и
  не дергает `GET .../audio`.
- `findOrThrow` смотрит `deletedAt IS NULL`: мягко удалённая
  композиция — `404`, как несуществующий id. Это не пустой агрегат с
  пустыми массивами.
- `fileUrl` внутри `clips` по-прежнему отсутствует в JSON, пока статус
  не `DONE` — не `null`. Тип ответа не выдумывает обязательное
  `fileUrl: string | null`.
- Presigned (`originalAudioUrl`, `fileUrl` картинок и готовых отрезков)
  в стор как постоянный адрес не класть: TTL по умолчанию 3600 с
  ([общие правила](../../02-staff-api.md#1-общие-правила)).
- Метод живёт рядом со стором композиций этапа 4 (тот же
  `compositionId`) или в том же корневом сторе. Второй HTTP-клиент не
  заводить.
- Правила «чем обновлять блок после мутации» — в
  [README этапа](./README.md#обновление-после-мутаций); эта задача их
  не реализует.

## Объём работы

- Метод стора (имя на усмотрение): принимает `id`, вызывает
  `GET /compositions/:id/full`, возвращает разобранный
  `CompositionFullResponseDto` (или эквивалентный тип клиента).
- При `404` / сетевой ошибке — тот же разбор ошибки клиента этапа 0;
  refresh и access не чистить.
- Тесты на моке `fetch`:
  - один запрос на путь с суффиксом `/full`;
  - успешный ответ с массивами `clips`, `images`, `notes` принимается
    как есть (в том числе пустые массивы);
  - ответ с `originalAudioUrl: null` и
    `originalAudioDurationSec: null` — успех; после вызова в сети нет
    `GET .../audio`;
  - `404` → ошибка наружу; `localStorage` refresh не тронут.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` проходит.
- В модуле стора нет вызова `GET .../audio` из метода полной карточки.
  Проверяется чтением модуля и тестом на `null` URL.
