# Задача 2 — Приёмка этапа 8

Этап: 8 — Сборка карточки композиции.
Зависимости: [задача 1](./01-post-mutation-refresh.md) (и транзитивно
первая загрузка карточки — [задача 4 этапа 4](../step-4/04-composition-card.md)
— и блоки мутаций этапов 5–7).
Ссылка на ТЗ: [DoD раздела «Этап 8»](../../03-technical-specification.md#этап-8--сборка-карточки-композиции).

## Зачем

Задача 1 закрывает стык обновления после мутаций на моке. DoD этапа —
другой контур: на живом `quizbeat-srv`, когда все блоки уже на экране
(этапы 4–7), ни одна мутация не оставляет на экране устаревших данных —
ни подменённый частичным ответом список, ни обнулённый соседний блок, ни
просроченный `fileUrl`. Без сервера стык легко остаётся зелёным в тестах
при случайном смешении снимков. Открытие карточки одним `GET .../full` и
пустые состояния уже проверены [приёмкой этапа 4](../step-4/06-step4-acceptance.md)
и здесь не переповторяются. Новой функциональности здесь нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| Прогон `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` со всеми блоками на одной композиции | Новые поля форм, новый маршрут, игрок, восстановление композиции |
| Исправление стыка, если задача 1 не складывается в DoD: смешение `fileUrl`, подмена блока частичным ответом мутации, обнуление соседнего блока `PATCH`-ом композиции | Открытие карточки одним `GET .../full`, пустые состояния, `404` — уже проверены [приёмкой этапа 4](../step-4/06-step4-acceptance.md) |
| Проверка тестов стыка мутаций из задачи 1 в общем `npm run test` | Подмена порта 5173 или базового URL |
| | Переписывание multipart / опроса / DnD / формы заметок сверх стыка этапа 8. Смена маршрута `/compositions/:id` |

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN`, учётки `ADMIN` и порта dev-сервера — общие
  для всех этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
  Учётка `ADMIN` тоже подходит: обе роли ведут композиции.
- Для проверки аудио и картинок нужен MinIO (как на приёмках этапов
  5–6).
- После загрузки картинок в сети должен появиться `GET .../images` (или
  согласованный полный набор), а не подмена списка телом `POST`. Тот же
  принцип — для отрезков (`GET .../clips`) и заметок (`GET .../notes`).
- `npm run test` — один прогон по `src/`: должны быть видны тесты стыка
  мутаций из задачи 1 (частичный `POST .../images` не затирает уже
  показанные; `PATCH` композиции не обнуляет `clips`). Отдельный «только
  приёмочный» набор DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задача 1 (и транзитивно все задачи
этапов 4–7). Кода сверх них не добавлять. Если пункт не сходится —
правится стык в файлах той задачи, которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тесты: частичный `POST .../images` не
  затирает уже показанные; `PATCH` композиции не обнуляет `clips`
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  (и MinIO, если проверяются файлы)
- На одной композиции, где уже есть трек, отрезки, картинки и заметки
  (заведённые на приёмках этапов 5–7 или заново): открыть карточку —
  все блоки показывают данные одного `GET .../full`
- Загрузить ещё одну картинку: на экране видны все картинки, включая
  прежние, не только новую; в сети — `GET .../images` (или согласованный
  полный набор), не тело `POST`
- Изменить название композиции (`PATCH /compositions/:id`): название
  обновилось, отрезки/картинки/заметки на экране не пропали и не
  обнулились
- Загрузить новый трек поверх существующего: длительность и волна
  обновились на новый файл, прежняя ссылка на аудио больше не
  используется; отрезки от старого трека остаются в списке как есть
  (сервер их не удаляет — см. [этап 5](../../03-technical-specification.md#этап-5--аудио-и-отрезки))
- Отправить новые точки на нарезку и дождаться `DONE`/`FAILED`; удалить
  один отрезок, одну картинку, одну заметку — в каждом случае экран
  показывает актуальный список без удалённого элемента и без потери
  соседних

Композиции и файлы, заведённые только для прохода, в конце имеет смысл
убрать с экрана, если они больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Мутации всех блоков без потери соседних данных —
  ручным проходом в браузере против запущенного `quizbeat-srv`, не
  только моком.
- В `npm run test` нет `.skip` на тестах стыка мутаций из задачи 1.
  Проверяется тем же прогоном.
