# Задача 6 — Приёмка этапа 2

Этап: 2 — Сотрудники.
Зависимости: [задача 3](./03-create-admin.md),
[задача 4](./04-role-and-activity.md) и
[задача 5](./05-reset-password.md) (и транзитивно список из
[задачи 2](./02-admins-list.md)).
Ссылка на ТЗ: [DoD раздела «Этап 2»](../../03-technical-specification.md#этап-2--сотрудники).

## Зачем

Задачи 1–5 по отдельности закрывают форму запроса и отказы на моке.
DoD этапа — другой контур: супер-админ заводит вторую учётку на живом
`quizbeat-srv`, входит под ней, меняет роль, деактивирует, активирует
снова и сбрасывает пароль. Под `ADMIN` пункта меню нет, а прямой URL
показывает отказ сервера. Стык легко остаётся зелёным в тестах, когда
`DELETE` на самом деле ушёл как `PATCH` или прямой заход `ADMIN` так и
не послал `GET`. Новой функциональности здесь нет.

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN` и порта dev-сервера — общие для всех
  этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
  Пароль заведённой в этом проходе учётки тоже в репозиторий не
  копируется.
- Вторая учётка — та, что создана с экрана в этом проходе, а не запись,
  добавленная в БД в обход `POST /admins`. Иначе создание остаётся
  непроверенным.
- После деактивации уже открытая вкладка той учётки может ещё ходить в
  API, пока жив её access. Приёмка проверяет другое: новый логин и
  refresh этой учётки не проходят, пока она неактивна, и снова проходят
  после активации. Сообщение неудачного логина — `Invalid credentials`,
  то же, что у неверного пароля.
- Прямой URL под `ADMIN` — это вставка `/admins` в адресную строку уже
  вошедшей сессии, не пункт меню. В сети один `GET /admins` с
  `Authorization`, ответ `403`, на экране `message` этого ответа, таблицы
  нет. Переход на логин значит, что клиент получил `401`: запрос ушёл
  без access, а не упёрся в отказ по роли.
- `npm run test` гоняется один раз по всему `src/`. В выводе должен быть
  тест видимости пункта меню по роли. Отдельный прогон «только
  приёмочных» DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–5. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест, что пункт «Сотрудники» виден
  только `SUPER_ADMIN`, и тест, что прямой заход `ADMIN` на `/admins`
  получает отказ и не рисует список
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  с сидом супер-админа
- Вход сидом: пункт «Сотрудники» открывает список. В сети
  `GET /admins` без параметра `isActive`
- Создание сотрудника с ролью `ADMIN` и паролем не короче 8: строка
  появляется в списке, в теле ответа пароля нет
- Выход, вход новой учёткой: пункта «Сотрудники» нет. Адрес `/admins`
  показывает `message` ответа `403`, таблицы нет. Смена своего пароля
  из шапки по-прежнему доступна
- Снова вход сидом. Смена роли этой учётки на `SUPER_ADMIN` и обратно
  на `ADMIN`: после повторного чтения списка в строке та роль, которая
  только что сохранена
- Деактивация при фильтре «все» (в query нет `isActive`): подтверждение
  не обещает мгновенно оборвать access; после согласия строка остаётся
  в списке со статусом неактивной. Логин этой учёткой даёт
  `Invalid credentials`. Повторная активация (`PATCH` с `isActive: true`,
  отдельного URL нет): логин тем же паролем открывает оболочку
- Сброс пароля этой учётки: старый пароль даёт `Invalid credentials`,
  новый входит. Сессия сида при этом на месте, на логин его не
  выбрасывает
- Когда активный `SUPER_ADMIN` в системе один (сид, а вторая учётка
  снова `ADMIN`), понижение или деактивация сида показывает
  `Cannot deactivate or demote the last active SUPER_ADMIN`. Роль и
  статус сида в списке не меняются
- Короткий пароль в создании и в сбросе (7 символов) запрос не шлёт

Учётку, заведённую для прохода, в конце имеет смысл деактивировать,
если она больше не нужна. Этот проход пароль сида не меняет: смена
своего пароля закрыта приёмкой этапа 1.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Создание, вход второй учёткой, роль, деактивация,
  активация, сброс пароля и прямой URL — ручным проходом в браузере
  против запущенного `quizbeat-srv`, не только моком.
- В `npm run test` нет `.skip` на тесте пункта меню и на тестах списка,
  создания, деактивации и сброса пароля. Проверяется тем же прогоном.
