# Задача 3 — Приёмка этапа 12

Этап: 12 — Исполнители вместо автора.
Зависимости: [задача 1](./01-composition-artists-field.md) (и
[задача 2](./02-artists-page.md), если сделана); серверный этап 17,
задачи 1–3, в `main`.
Ссылка на ТЗ: [DoD раздела «Этап 12»](../../03-technical-specification.md#этап-12--исполнители-вместо-автора).
Условия приёмки (сид, порт, образ сервера) — [acceptance-preconditions.md](../acceptance-preconditions.md).

## Зачем

Сверка клиента с реальным ответом сервера и проверка миграции данных глазами
пользователя. После этой приёмки серверная задача 4 удаляет колонку `author`,
поэтому пройти её нужно до неё и на данных с реальными значениями `author`.
Новой функциональности нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| `lint`, `test`, `build` и ручной проход против `quizbeat-srv` с этапом 17 (задачи 1–3) | Игровой клиент |
| Исправление стыка, если форма ответа расходится с сервером | Новые поля и экраны |

## ⚠ Технические нюансы и ограничения

- **Проход на копии данных с реальными значениями `author`,** не на пустой
  БД: иначе перенос и составные значения не проверяются.
- **Образ `quizbeat-app` должен быть собран из `main` с этапом 17** (см.
  [acceptance-preconditions.md](../acceptance-preconditions.md#образ-сервера)),
  иначе проход идёт против старого `author`.
- Данные прохода (исполнители, композиции) в конце удаляются; перенесённых
  из старых значений не трогать.

## Объём работы

Ручной проход под `SUPER_ADMIN`: список композиций показывает исполнителей из
перенесённых значений `author`; поиск находит и по названию, и по
исполнителю; создание композиции без исполнителей (черновик и
публикация); создание с двумя исполнителями, один из которых создан в поле
«на лету», порядок сохраняется после F5 и в карточке; смена порядка и снятие
всех (`artistIds: []`); дубль имени в другом регистре — без ошибки на экране;
диалог удаления показывает подпись. Если задача 2 сделана: переименование
составного значения и невозможность удалить используемого исполнителя.
Под `ADMIN`: тот же сценарий создания. Результат записать в
[status.md](../status.md).

## Критерии готовности

- `npm run lint`, `npm run test`, `npm run build` без ошибок.
- Сценарий выше пройден на живом сервере; запросы в вкладке сети совпадают
  с картой `staff-api.md` (`artistIds` в нужном порядке, без `author`).
- Этап 12 отмечен в [status.md](../status.md); серверная задача 4 может
  стартовать.
