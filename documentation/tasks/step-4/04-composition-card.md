# Задача 4 — Карточка композиции

Этап: 4 — Композиции.
Зависимости: [задача 2](./02-compositions-list.md) (переход со строки
списка) и методы `full` / правки из
[задачи 1](./01-compositions-store.md); выбор тегов — стор
[этапа 3](../step-3/01-tags-store.md).
Ссылка на ТЗ: [раздел «Этап 4»](../../03-technical-specification.md#этап-4--композиции)
(карточка открывается `GET .../full`; `PATCH` названия, автора, статуса и
набора тегов; снятие последнего тега — пустой `tagIds`).
Карта: строки `GET .../full` и `PATCH /compositions/:id` в
[композициях](../../02-staff-api.md#5-композиции).
DTO —
[`UpdateCompositionDto`](../../../../quizbeat-srv/src/compositions/dto/update-composition.dto.ts),
[`CompositionFullResponseDto`](../../../../quizbeat-srv/src/compositions/dto/composition-full-response.dto.ts),
замена тегов — в
[`CompositionsService.update`](../../../../quizbeat-srv/src/compositions/compositions.service.ts).

## Зачем

Правка композиции — не строковый диалог списка: на этот же маршрут позже
сядут аудио, картинки и заметки. Карточка открывается единственным
способом, каким будет пользоваться весь дальнейший план — одним
`GET .../full` — а не временным стыком через список, который потом
пришлось бы заменять: сервер уже отдаёт агрегат одним запросом, и нет
причины сперва подражать ему повторным `GET /compositions`. Отдельного
`GET /compositions/:id` на сервере нет — его не выдумывать. Создание и
удаление сюда не входят: у них другие действия и другие тесты.

## Границы задачи

| Входит | Не входит |
|---|---|
| Маршрут `/compositions/:id` и экран правки: название, автор, статус, набор тегов | Создание — [задача 3](./03-create-composition.md) |
| Монтирование карточки (переход со списка, прямой заход, F5) — один вызов `GET /compositions/:id/full` | Удаление — [задача 5](./05-delete-composition.md) |
| `location.state` со строки списка — только как мгновенный заголовок (название/автор) на время запроса, не как источник данных карточки | Выдуманный `GET /compositions/:id`. На сервере его нет |
| `PATCH /compositions/:id`; снятие последнего тега шлёт `tagIds: []` | Отображение блоков `clips` / `images` / `notes` / аудио из ответа `full` — [этапы 5–7](../../03-technical-specification.md#этап-5--аудио-и-отрезки). Эта задача данные получает и хранит в состоянии карточки, но не рисует |
| `404` (нет id / мягко удалена) — состояние «не найдена» со ссылкой на список | Опрос, DnD, формы блоков — их ещё нет на экране |

## ⚠ Технические нюансы и ограничения

- Загрузка — см.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
  Кратко: при монтировании `/compositions/:id` (со state со списка, с
  прямого URL, после F5) — один `GET /compositions/:id/full`.
  `location.state` со списка можно показать как мгновенный заголовок,
  пока идёт запрос, но данные экрана (тегами, статусом и т.д.) — только
  из ответа `full`. `404` — «не найдена» и ссылка на `/compositions`, не
  скелет.
- Поля формы заполняются из ответа `full`: `title`, `author`, `status`,
  теги из массива `tags` (id для выбора — `tag.id`). Названия тегов в
  контроле — по `locale`, не по индексу. Ответ также содержит `clips` /
  `images` / `notes` / `originalAudioUrl` / `originalAudioDurationSec` —
  эта задача сохраняет их в состоянии карточки (например, в сторе
  композиции), но не рисует: соответствующих блоков ещё нет на экране,
  их добавят задачи этапов 5–7, читая те же данные.
- Сохранение: если человек менял набор тегов, в `PATCH` уходит
  `tagIds` — полный текущий набор id, в том числе `[]` после снятия
  последнего. Если набор не трогали, ключа `tagIds` в JSON нет: сервер
  иначе не отличит разницу «не меняли» и «очистили». Название, автор и
  статус уходят, когда их меняли / всегда вместе с сохранением формы —
  достаточно слать актуальные значения полей формы; пустые название или
  автор на сервер не уходят (русское сообщение, без `fetch`).
- Неизвестный тег — `400` с
  `One or more tagIds do not reference an existing tag`. Нет строки или
  она уже мягко удалена — `404` (тот же `findOrThrow` с
  `deletedAt IS NULL`, что и на открытии). Сообщение на карточке, без
  очистки сессии.
- Успех `PATCH` (`200`): ответ —
  [`CompositionResponseDto`](../../../../quizbeat-srv/src/compositions/dto/composition-response.dto.ts)
  **без** `clips` / `images` / `notes` / `originalAudioUrl`. Им
  обновляются только поля композиции и `tags` в состоянии карточки —
  этим ответом нельзя затирать уже сохранённые данные блоков. Список при
  возврате назад перечитывается сам при монтировании; ответ `PATCH` в
  таблицу списка из карточки не подмешивается.
- Presigned-поля ответа `full` (`originalAudioUrl`) в состояние как
  постоянный адрес не класть: TTL по умолчанию 3600 с — актуально для
  задач этапа 5, эта задача только хранит то, что пришло.
- Текст полей рисуется React-текстом, без `dangerouslySetInnerHTML`.
- На карточке нет загрузки файла, списка отрезков, картинок и заметок —
  их блоков ещё нет, только сохранённые для них данные.
- Экран списка общий с задачами 3 и 5. Эта задача добавляет действие
  строки «Изменить» (переход на карточку) и маршрут. При конфликте
  слияния — после задачи 3, до задачи 5, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- Со строки списка действие «Изменить» открывает `/compositions/:id`,
  передавая строку в `location.state` для мгновенного заголовка.
- Карточка при монтировании (с state и без) вызывает метод `full` из
  [задачи 1](./01-compositions-store.md) с `id` из пути и заполняет
  состояние экрана его ответом; `state` используется только для
  заголовка на время запроса.
- Форма: название, автор, статус (`DRAFT` / `PUBLISHED` с русскими
  подписями), мультивыбор тегов из стора тегов. Сохранение вызывает
  метод правки стора и обновляет только поля композиции и `tags` в
  состоянии карточки.
- UI: индикатор только пока идёт `GET .../full`; при `404` — «не
  найдена» со ссылкой на `/compositions`; при сетевой ошибке —
  сообщение, не вечный скелет.
- Тесты:
  - монтирование `/compositions/:id` (с state и без) вызывает ровно
    один `GET .../full` и не вызывает `GET /compositions` (список) и не
    вызывает `GET /compositions/${id}` без суффикса;
  - `404` на `GET .../full` — состояние «не найдена», нет бесконечного
    индикатора;
  - сохранение после снятия всех тегов шлёт JSON с `"tagIds":[]`;
  - сохранение без изменения тегов ключа `tagIds` не содержит;
  - смена статуса на `PUBLISHED` шлёт `status: "PUBLISHED"`;
  - пустое название не вызывает `fetch`;
  - `400` про неизвестный тег показывает `message` на карточке;
  - успешный `PATCH` не затирает уже сохранённые в состоянии `clips` /
    `images` / `notes` (ответ `PATCH` их не содержит — стор не должен
    подставлять на их место `undefined`).

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят: маршрут `/compositions/:id`
  в сборке.
- В модуле карточки — ровно один вызов `GET .../full` на монтирование и
  нет `GET` на `/compositions` (список) или `/compositions/${id}` без
  суффикса как источника данных. Проверяется чтением модуля и тестом на
  моке сети.
