# Задача 3 — Оболочка: MUI, MobX и маршрут-заглушка

Этап: 0 — Каркас.
Зависимости: [задача 1](./01-project-scaffold.md) (вход `src/main.tsx`,
скрипты, jsdom, Testing Library).
Ссылка на ТЗ: [раздел «Этап 0»](../../03-technical-specification.md#этап-0--каркас)
(MobX, MUI с локалью `ruRU`, react-router, каркас страницы, маршрут-заглушка).

## Зачем

DoD этапа требует открыть оболочку в браузере, а этап 1 должен добавить
логин и выход в уже существующие роутер, тему и корневой стор. Если
собрать это вместе с HTTP-клиентом, пропадает параллельность с
[задачей 2](./02-http-client.md): обе стали бы править `src/main.tsx`.
Оболочка от клиента не зависит — на этом этапе она в API не ходит.

## Границы задачи

| Входит | Не входит |
|---|---|
| Тема MUI и локаль `ruRU`, подключенные в дереве приложения | Экран логина, выход, восстановление сессии — [этап 1](../../03-technical-specification.md#этап-1--сессия-сотрудника) |
| Корневой стор MobX и доступ к нему из React | Стор сессии, разбор JWT, пункт меню сотрудников — этап 1. Поле `session` в корневой стор не добавлять «впрок» |
| Каркас страницы и один маршрут-заглушка на `/` | Справочники, композиции и любые вызовы staff-API |
| Замена пустого рендера из задачи 1 | Правки `src/api/**` — это [задача 2](./02-http-client.md) |

## ⚠ Технические нюансы и ограничения

- Пакет `mobx-react` (тот, где есть готовый `Provider`) не ставится.
  Нужны `mobx` и `mobx-react-lite`. Провайдер — свой React context вокруг
  корневого стора. Импорт `Provider` из неотмеченного в зависимостях
  пакета либо не соберётся, либо подтянет вторую связку с MobX.
- Локаль `ruRU` берётся из установленного `@mui/material`, путь экспорта
  сверяется с типами этой версии, а не по памяти. Подключение — в
  `createTheme`, и этот же `theme` передаётся в `ThemeProvider`. Создать
  тему с локалью и тут же отрисовать компоненты мимо неё — частый способ
  получить английские строки MUI при русских собственных подписях.
- Зависимости MUI тащат peer-пакеты emotion (`@emotion/react`,
  `@emotion/styled` — фактический список смотреть в `peerDependencies`
  установленной версии). Без них dev-сервер падает уже на импорте
  `@mui/material`, хотя тип ошибки выглядит как проблема бандлера.
- `src/main.tsx` создан в задаче 1 как пустой рендер. Здесь он заменяется
  на провайдеры (тема, стор, роутер) и оболочку. Задача 2 этот файл не
  меняет; если обе задачи сливаются в одну ветку, конфликт ожидается
  только в `package.json` (новые dependencies этой задачи поверх каркаса).
- Оболочка не импортирует `src/api/**`. Иначе заглушка легко обрастает
  запросом «проверить, что сервер жив», а открытие страницы без
  запущенного `quizbeat-srv` начинает выглядеть как сломанный каркас.
- Текст заглушки — обычная разметка React. `dangerouslySetInnerHTML` для
  него не используется: на следующих этапах так же рендерятся строки,
  пришедшие с сервера, и исключение лучше не заводить на пустом экране.

## Объём работы

- Зависимости: `mobx`, `mobx-react-lite`, `@mui/material` и его peer-пакеты
  по установленной версии, `react-router` того мажора, который ставится.
  API роутера сверять с типами этой версии (имена `createBrowserRouter` /
  `BrowserRouter` между мажорами расходятся).
- `src/app/theme.ts` — тема с локалью `ruRU`.
- `src/stores/root-store.ts` — класс корневого стора без полей домена.
  Контекст и хук доступа — рядом, в `src/app/` или `src/stores/`, одним
  модулем, чтобы этап 1 добавлял дочерний стор в класс, а не искал второй
  контекст.
- `src/app/AppShell.tsx` — каркас страницы на MUI: шапка с названием
  «Админка QuizBeat» и область содержимого с короткой русской фразой, что
  рабочие экраны появятся на следующих этапах. Кнопок входа и выхода нет.
- Маршрут `/` показывает эту оболочку. Неизвестный путь не оставляет
  белый экран: та же оболочка и явная русская пометка, что адреса нет.
- `src/main.tsx` монтирует провайдеры и роутер. `index.html`: `lang="ru"`,
  заголовок вкладки про админку QuizBeat.
- Тест Testing Library на том же дереве провайдеров, что и `main.tsx`:
  - на `/` виден заголовок «Админка QuizBeat»;
  - полей email и пароля нет;
  - хук стора внутри дерева возвращает экземпляр корневого стора;
  - локаль темы совпадает с `ruRU` установленного пакета (сравнение с
    импортированным объектом локали, а не с захардкоженной русской
    строкой, которая в следующем миноре MUI может смениться).

## Критерии готовности

- Тест из объёма работы проходит через `npm run test`.
- `npm run lint` и `npm run build` проходят: в сборку входят тема, стор
  и маршрут.
- В `src/app/` и `src/stores/` нет обращения к `/auth/staff` и нет импорта
  HTTP-клиента. Проверяется поиском по этим каталогам.
- В корневом сторе нет полей сессии (`accessToken`, `refreshToken`,
  `role`). Проверяется чтением `src/stores/root-store.ts`.
