## Зачем

DoD этапа держится на форме: без обоих текстов запрос не уходит, с
обоими — уходит. Создание и правка делят одни и те же два поля.
Две задачи собрали бы это правило дважды и правили бы один диалог.
Порядок и удаление сюда не входят: у них другие действия и другие
тесты. Пока нет списка из задачи 2, форму некуда поставить.

| Входит | Не входит |

## ⚠ Технические нюансы и ограничения

- Форма одна, два входа: кнопка «Создать» и действие «Изменить» на
  строке. Правка заполняется из строки списка: оба текста по полю
  `locale`, не по индексу. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- Создание отправляет `{ translations }` из двух элементов, локали
  `ru` и `en`, у каждой поле **`text`**. Правка отправляет тот же
  состав на `PATCH .../notes/:noteId`, даже если человек изменил только
  один текст. Опустить `translations` или отправить одну локаль —
  `400`. Поля `name` в JSON нет.
- Пустое любое из двух полей на сервер не отправляется, на форме
  русское сообщение. Пробелы по краям клиент не обязан обрезать: сервер
  принимает непустую строку как есть (`@IsNotEmpty()`).
- Успех создания — `201`, успех правки — `200`. Диалог закрывается,
  список обновляется ответом мутации или повторным `GET .../notes` —
  достаточно одного актуального массива на блоке.
- `400` с
  `Translations must include exactly one entry per locale (ru, en), without duplicates`
  (при обходе клиентской проверки) и `404` показывают `message` как
  есть; диалог при отказе валидации остаётся открыт.
- Общий файл — блок задачи 2. Вливать после 02, до 04 и 05 при
  конфликте, см. [README](./README.md#почему-такой-порядок).

## Объём работы

- На блоке кнопка «Создать» открывает форму с пустыми полями. На строке
  действие «Изменить» открывает ту же форму, заполненную обоими
  текстами этой строки. Подписи русские.
- Отправка создания вызывает метод стора с `{ translations }`.
  Отправка правки — с id строки и тем же составом тела. Проверка до
  запроса: пустой `text` `ru` или `en` — русское сообщение, `fetch` не
  вызывается.
- При `201` и при `200` диалог закрыт, список актуален. При `400` /
  `404` на форме / блоке видна строка `message`.
- Тесты:
  - пустой текст `en` при заполненном `ru` не вызывает `fetch`; то же
    для пустого `ru`;
  - создание шлёт две локали с полем `text` и не шлёт `name`;
  - правка, в которой изменён только русский текст, шлёт и `ru`, и
    `en`;
  - `201` закрывает диалог и обновляет список.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test` — в том числе
  тест «запрос с одним переводом не уходит», которого требует DoD
  этапа.
- `npm run lint` и `npm run build` проходят.
- В модуле формы у обоих переводов есть поле `text` и нет поля `name`.
  Проверяется чтением формы.
