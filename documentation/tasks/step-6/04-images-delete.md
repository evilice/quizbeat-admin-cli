# Задача 4 — Удаление картинки с подтверждением

Этап: 6 — Изображения композиции.
Зависимости: [задача 2](./02-images-upload-and-list.md) (строка
списка); метод `DELETE` из
[задачи 1](./01-images-store.md).
Ссылка на ТЗ: [раздел «Этап 6»](../../03-technical-specification.md#этап-6--изображения-композиции)
(удаление `DELETE .../images/:imageId`, `204`; DoD — удаление убирает
карточку).
Карта: строка `DELETE` в
[картинках](../../02-staff-api.md#7-картинки).
Сервис —
[`CompositionImagesService.remove`](../../../../quizbeat-srv/src/composition-images/composition-images.service.ts).

## Зачем

DoD этапа требует удалить картинку с экрана. Отдельная задача не ломает
тест полного `imageIds` из задачи 3 и фиксирует отличие пустого `204`
от мягкого удаления композиции.

## Границы задачи

| Входит | Не входит |
|---|---|
| Действие «Удалить» на элементе списка: подтверждение, `DELETE .../images/:imageId`, обновление списка | Мягкое удаление композиции — [этап 4](../step-4/05-delete-composition.md) |
| Показ `404` / иной ошибки API строкой `message` | Перетаскивание порядка — [задача 3](./03-images-reorder.md) |
| | Заметки — [этап 7](../../03-technical-specification.md#этап-7--заметки-а-знали-ли-вы) |

## ⚠ Технические нюансы и ограничения

- Удаление жёсткое, успех — `204` без тела. Это не `200` с `deletedAt`
  как у композиции. После успеха элемент пропадает из списка
  (перечитать `GET .../images` или убрать локально после успешного
  вызова — достаточно одного согласованного способа).
- Подтверждение — по-русски: картинка исчезнет необратимо. Отмена не
  вызывает `fetch`.
- `404` (нет картинки / чужая композиция / мягко удалённая композиция)
  — на блоке, без очистки сессии.
- Общий файл — список задачи 2. Вливать после 02; при конфликте с
  задачей 3 — после неё, см. [README](./README.md#почему-такой-порядок).

## Объём работы

- В элементе списка: удаление с подтверждением.
- Успех → списка без этой картинки.
- Тесты:
  - согласие на удаление вызывает `DELETE` на путь с `imageId`, успех
    при `204`;
  - отмена подтверждения не вызывает `fetch`;
  - `404` показывает `message`.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` проходит.
- В UI удаления картинки нет вызова `DELETE /compositions/:id`
  (удаление композиции). Проверяется чтением модуля / тестом пути.
