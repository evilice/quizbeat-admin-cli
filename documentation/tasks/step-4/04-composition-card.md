## Зачем

Правка композиции — не строковый диалог списка: на этот же маршрут
позже сядут аудио, картинки и заметки, а этап 8 сменит первую загрузку
на `GET /full`. Отдельного `GET /compositions/:id` на сервере нет — его
не выдумывать и `GET /full` на этом этапе не вызывать. Карточка
фиксирует маршрут и временный стык загрузки, чтобы этапы 5–8 не
выбирали экран заново. Создание и удаление сюда не входят: у них другие
действия и другие тесты.

## ⚠ Технические нюансы и ограничения

- Маршрут и стык загрузки — см.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
  Кратко: из списка — `location.state` со строкой ответа плюс search
  карточки копирует текущие `search` / `status` / `tagIds` / `page` /
  `limit` списка. Без state (прямой URL, F5) — тот же
  `GET /compositions` с этими query, поиск `items` с нужным `id`. Нет в
  `items` — «не найдена» и ссылка на `/compositions`, не скелет и не
  `GET .../full`. Этап 8 заменяет этот стык одним `GET /full`.
- Поля формы заполняются из строки: `title`, `author`, `status`, теги
  из массива `tags` ответа (id для выбора — `tag.id`). Названия тегов в
  контроле — по `locale`, не по индексу.
- Сохранение: если человек менял набор тегов, в `PATCH` уходит
  `tagIds` — полный текущий набор id, в том числе `[]` после снятия
  последнего. Если набор не трогали, ключа `tagIds` в JSON нет: сервер
  иначе не отличит разницу «не меняли» и «очистили». Название, автор и
  статус уходят, когда их меняли / всегда вместе с сохранением формы —
  достаточно слать актуальные значения полей формы; пустые название или
  автор на сервер не уходят (русское сообщение, без `fetch`).
- Неизвестный тег — `400` с
  `One or more tagIds do not reference an existing tag`. Нет строки или
  она уже мягко удалена — `404`. Сообщение на карточке, без очистки
  сессии.
- Успех `200`: форма показывает актуальные поля из ответа (в том числе
  `tags`). Список при возврате назад перечитывается сам при монтировании;
  ответ `PATCH` в таблицу списка из карточки не подмешивается.
- Текст полей рисуется React-текстом, без `dangerouslySetInnerHTML`.
- На карточке нет загрузки файла, списка отрезков, картинок и заметок.
- Экран списка общий с задачами 3 и 5. Эта задача добавляет действие
  строки «Изменить» (переход на карточку) и маршрут. При конфликте
  слияния — после задачи 3, до задачи 5, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- Со строки списка действие «Изменить» открывает `/compositions/:id` с
  state строки и search из текущих фильтров списка.
- Карточка с state сразу показывает поля без лишнего `GET`, пока state
  есть. Без state — вызывает список стора с query из search и ищет id;
  при отсутствии строки — состояние «не найдена» со ссылкой на список.
- Форма: название, автор, статус (`DRAFT` / `PUBLISHED` с русскими
  подписями), мультивыбор тегов из стора тегов. Сохранение вызывает
  метод правки стора.
- Тесты:
  - переход со списка кладёт в navigate state объект с `id` этой строки
    и не вызывает `GET .../full`;
  - монтирование `/compositions/:id` без state с query списка вызывает
    `GET /compositions` с этими параметрами и не вызывает
    `GET /compositions/:id` и не вызывает `GET .../full`;
  - если в `items` нет нужного id — на экране состояние «не найдена»,
    нет бесконечного индикатора загрузки;
  - сохранение после снятия всех тегов шлёт JSON с `"tagIds":[]`;
  - сохранение без изменения тегов ключа `tagIds` не содержит;
  - смена статуса на `PUBLISHED` шлёт `status: "PUBLISHED"`;
  - пустое название не вызывает `fetch`;
  - `400` про неизвестный тег показывает `message` на карточке.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят: маршрут `/compositions/:id`
  в сборке.
- В модуле карточки нет вызова пути `/full` и нет `GET` на
  `/compositions/${id}` без суффикса. Проверяется чтением модуля.
  Комментарий или явная пометка в коде/тесте, что стык загрузки заменит
  этап 8, — достаточна одна фраза рядом с загрузкой.
