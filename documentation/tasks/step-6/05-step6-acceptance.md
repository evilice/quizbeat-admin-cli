# Задача 5 — Приёмка этапа 6

Этап: 6 — Изображения композиции.
Зависимости: [задача 3](./03-images-reorder.md) и
[задача 4](./04-images-delete.md) (и транзитивно загрузка/список из
[задачи 2](./02-images-upload-and-list.md) и стор из
[задачи 1](./01-images-store.md)).
Ссылка на ТЗ: [DoD раздела «Этап 6»](../../03-technical-specification.md#этап-6--изображения-композиции).

## Зачем

Задачи 1–4 по отдельности закрывают форму запроса и UI на моке. DoD
этапа — другой контур: на живом `quizbeat-srv` с реальными jpg/png/webp
можно загрузить несколько картинок, перетащить порядок, увидеть
совпадение с повторным `GET`, удалить карточку. Без сервера и файлов
стык легко остаётся зелёным в тестах при поле `file` или частичном
`imageIds`. Новой функциональности здесь нет.

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN`, учётки `ADMIN` и порта dev-сервера — общие
  для всех этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
  Учётка `ADMIN` тоже подходит: обе роли ведут картинки.
- Рядом с `quizbeat-srv` нужен рабочий MinIO. Без хранилища превью по
  `fileUrl` не откроются — это среда сервера, не повод менять способ
  загрузки.
- В сети загрузки — multipart с полем `files`, ответ `201` с
  `fileUrl` сразу. В сети порядка — JSON `{ imageIds: [...] }` полный
  набор. В сети карточки при открытии — ровно один `GET .../full`, из
  него же блок берёт начальный список картинок; `GET .../images`
  появляется в сети только после мутаций (загрузка, порядок, удаление).
- `npm run test` — один прогон по `src/`: должны быть видны тест поля
  `files` и тест полного `imageIds`. Отдельный «только приёмочный»
  набор DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–4. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест multipart-поля `files` (не
  `file`) и тест, что в `imageIds` уходит полный текущий набор в новом
  порядке
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
- Вход staff → композиции → карточка существующей или новой композиции.
  В сети при открытии карточки — ровно один `GET .../full`, без
  отдельного `GET .../images` на маунте; блок картинок — под блоками
  этапа 5
- Загрузка нескольких реальных файлов (jpg, png или webp, разумный
  размер, не больше 10 за раз): в сети `POST .../images` с полем
  `files`, `201`, на экране превью по `fileUrl`
- Перетащить порядок: в сети `PATCH .../images/order` с полным
  `imageIds`; повторный `GET .../images` совпадает с экраном
- Удаление одной картинки: подтверждение, в сети `DELETE` и `204`,
  карточки/превью нет после обновления списка
- (Опционально.) Попытка выбрать SVG или сверхлимит — либо клиент не
  шлёт, либо на блоке виден `message` сервера; сессия жива

Композиции и картинки, заведённые только для прохода, в конце имеет
смысл удалить с экрана, если они больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Загрузка, порядок, удаление — ручным проходом в
  браузере против запущенного `quizbeat-srv` с реальными файлами, не
  только моком.
- В `npm run test` нет `.skip` на тесте поля `files`, на тесте полного
  `imageIds` и на тесте `204` удаления. Проверяется тем же прогоном.
