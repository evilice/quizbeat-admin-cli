# Задача 1 — Страница «Хранилище»: предпросмотр и очистка

Этап: 11 — Очистка хранилища.
Зависимости: серверный этап 16,
[задача 2](../../../../quizbeat-srv/documentation/tasks/step-16/02-storage-orphan-sweep.md)
(`POST /storage/sweep`); [HTTP-клиент](../step-0/02-http-client.md);
[роль в оболочке](../step-1/04-role-menu.md).
Ссылка на ТЗ: [раздел «Этап 11»](../../03-technical-specification.md#этап-11--очистка-хранилища).
Карта: раздел «Хранилище» в
[staff-api.md](https://github.com/evilice/quizbeat-docs/blob/main/api/staff-api.md)
(появляется в серверной задаче 2). Поля запроса и ответа здесь не
повторяются.

## Зачем

Сборка мусора необратимо удаляет файлы, поэтому экран должен сначала показать,
что будет удалено, и только потом дать удалить. Выделено одной задачей:
стор, страница и меню связаны одним сценарием и одной ролью, делить их
между задачами нет смысла (приёмка — отдельно, [задача 2](./02-step11-acceptance.md)).

## Границы задачи

| Входит | Не входит |
|---|---|
| Стор `storage`: вызов `POST /storage/sweep` с `apply: false` и `true`, состояния «идёт запрос», «предпросмотр», «итог», ошибка | Изменение сервера |
| Страница «Хранилище»: «Проверить», результат предпросмотра (файлы и объём по префиксам и в сумме), «Удалить» с подтверждением, итог (удалено файлов, освобождено, число ошибок) | История запусков, повтор итога после перезагрузки страницы |
| Пункт меню «Хранилище» и маршрут `/storage` только для `SUPER_ADMIN` | Свободное место диска сервера |
| Формат размера (Б, КБ, МБ, ГБ) — одна функция | Фильтры, расписание, автозапуск |

## ⚠ Технические нюансы и ограничения

- **Предпросмотр — это `POST`, а не `GET`.** Он не удаляет, но роль и
  `apply` обязательны в теле; поле `apply` всегда передаётся явно
  `false` / `true`, значения по умолчанию на клиенте нет.
- **Кнопка «Удалить» недоступна без свежего предпросмотра** и при нулевом
  результате. После итога предпросмотр сбрасывается: повторное удаление
  требует новой проверки.
- **Итог показывает ответ `apply: true`**, а не числа предпросмотра — набор
  кандидатов между вызовами мог измениться. Если `failed > 0`, итог говорит
  об этом отдельной строкой, как о предупреждении, не как об успехе без оговорок.
- **`409`** — другой запуск уже идёт: сообщение экрана, кнопки снова доступны,
  без автоповтора. **`403`** — не очищать сессию (как у сотрудников); вне
  `SUPER_ADMIN` страница в принципе недоступна.
- **Запрос долгий.** Без короткого таймаута, как у
  [видео](https://github.com/evilice/quizbeat-docs/blob/main/api/staff-api.md#9-видео);
  кнопки заблокированы на время запроса, повтор вручную невозможен.
- **Страница сотрудников — образец роли:** меню скрывает пункт
  (`PagesMenu.tsx`), но маршрут тоже обязан закрывать прямой заход по
  `/storage` для `ADMIN`; проверить, как это делает `AdminsPage`.
- Стор регистрируется в `src/shared/store/root-store.ts` рядом с остальными.

## План реализации

1. **Разведка (правило 1).** Прочитать модуль `admins` (стор, `AdminsPage`,
   как закрывается доступ ролью, диалог подтверждения в
   `reset-password/ResetPasswordDialog.tsx`), `api-client.ts` (JSON, `403`,
   таймаут), `PagesMenu.tsx`, `routes.tsx`. Прочитать раздел «Хранилище» в
   `staff-api.md` и DTO сервера — если форма ответа разошлась с этой
   задачей, верен код сервера (CLAUDE.md проекта).
2. **Тесты сначала (на моке `fetch`).** Стор: предпросмотр шлёт `apply:
   false`, удаление — `apply: true`; состояния и сброс предпросмотра после
   итога; `409` и `403` разбираются; повторный вызов во время запроса
   игнорируется. Страница: «Удалить» неактивна без предпросмотра и при нуле,
   подтверждение показывает числа, итог выводит число запуска; меню и маршрут
   скрыты для `ADMIN`.
3. **Стор `storage`** (`makeAutoObservable`, как `TagsStore`): методы
   `preview()` и `sweep()`, типы ответа, состояние запроса и результата.
4. **Формат размера** — отдельная функция с тестом (0 Б, граница КБ/МБ/ГБ).
5. **Страница `StoragePage`:** кнопка «Проверить» → таблица по префиксам
   (файлы, объём) и итог → «Удалить N файлов (X МБ)» → диалог подтверждения →
   итог «Удалено / Освобождено / Ошибок».
6. **Меню и маршрут.** Пункт `{ label: 'Хранилище', to: '/storage', role:
   'SUPER_ADMIN' }`, маршрут `/storage`, закрытый для не-`SUPER_ADMIN`.
7. **Регистрация стора** в `root-store.ts`; документация; `npm run test`,
   `lint`, `build`; `/code-review` (правило 7) и Impact; без подтверждения
   не коммитить.

## Критерии готовности

- `npm run test`, `npm run lint`, `npm run build` проходят.
- Тесты на моке: предпросмотр шлёт `apply: false`, удаление — `apply: true`;
  «Удалить» недоступна без предпросмотра и при нулевом результате;
  подтверждение показывает числа; итог берётся из ответа удаления; `failed > 0`
  показывается предупреждением; `409` и `403` разобраны.
- Тесты: пункт меню и маршрут `/storage` недоступны для `ADMIN`.
- Ручной проход на живом сервере — в [задаче 2](./02-step11-acceptance.md).
