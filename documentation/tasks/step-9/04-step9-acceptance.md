# Задача 4 — Приёмка этапа 9

Этап: 9 — Видео композиции.
Зависимости: [задача 3](./03-saved-video-block.md) (и транзитивно
задачи 1–2); серверный этап 14 в `main`.
Ссылка на ТЗ: [DoD раздела «Этап 9»](../../03-technical-specification.md#этап-9--видео-композиции).

## Зачем

Тесты на моке не ловят стык с реальным сервером: имена полей multipart,
дробные секунды, время синхронной обрезки большого файла, реальное
воспроизведение результата браузером, отсутствие исходника на сервере.
Новой функциональности нет.

## Границы задачи

| Входит                                                                                           | Не входит           |
| ------------------------------------------------------------------------------------------------ | ------------------- |
| `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` с реальными mp4 и webm | Игровой клиент      |
| Исправление стыка, если задачи 1–3 не складываются в DoD                                         | Новые поля и экраны |

## Объём работы

Ручной проход в браузере:

1. Выбрать mp4 (несколько десятков МБ) → играет локально, длительность
   верна. Выбрать отрезок с дробными границами (например 1.5–6.0 с),
   проиграть его → сохранить.
2. После сохранения виден плеер с результатом: длительность ≈ 4.5 с,
   проигрывается именно выбранный фрагмент (сверить по содержимому).
3. F5 → видео на месте (из `GET /full`).
4. В MinIO для композиции ровно один объект видео, исходника нет
   (проверить по содержимому бакета).
5. Заменить файлом webm с другим отрезком → играет новый, прежний
   объект в MinIO удалён.
6. Файл mp3 вместо видео и отрезок длиннее максимума → понятные
   ошибки, прежнее видео не пострадало.
7. Удалить → пустое состояние, повторный `GET /full` даёт `null`.
8. Время ответа обрезки на самом большом реалистичном файле — записать
   в итог.
9. Расхождение длительности клиента и сервера: файл, у которого длительность
   контейнера или аудиодорожки больше, чем у видеопотока. Клиент берёт
   длительность из `<video>`, сервер — из своей пробы (`ffprobe`), поэтому
   отрезок «весь ролик» по умолчанию может получить `400`
   (`endSec` больше длительности видео) уже после долгой загрузки. Проверить
   на таком файле, записать в итог, воспроизводится ли это; при
   воспроизведении завести отдельную задачу (клиент серверную длительность
   заранее не знает), в этом этапе не чинить.

Результат записать в [status.md](../status.md).

## План работы

Задача без кода (новой функциональности нет): прогон автоматических проверок,
затем ручной сценарий из «Объёма работы» против живого стека. Бюджет —
одна сессия; отклонения чинятся отдельными коммитами с префиксом `fix:`.

**Шаги.**

1. **Предусловия.** Серверный этап 14 в `main` `quizbeat-srv`; стек
   поднят по [acceptance-preconditions.md](../acceptance-preconditions.md)
   (Postgres, MinIO, Redis, ffmpeg доступен серверу — **без ffmpeg `422`
   на обрезке**, это не дефект клиента); `VITE_API_BASE_URL` указывает на
   сервер, порт клиента `5173` (CORS). Сверить лимиты стенда
   (`STORAGE_MAX_VIDEO_SIZE_BYTES`, `VIDEO_MAX_CLIP_DURATION_SEC`,
   `VIDEO_MAX_RESULT_SIZE_BYTES`) — при отличии от дефолтов поправить
   тестовые файлы, а не код.
2. **Автоматика.** `npm run lint`, `npm run test`, `npm run build` — коды
   возврата 0; прежнее предупреждение `use-app-shell.ts` не новое.
3. **Тестовые файлы.** mp4 (~30–50 МБ), webm (~10 МБ), самый большой
   реалистичный mp4 (для замера времени), mp3 вместо видео, видео длиннее
   60 с для проверки отклонения длины отрезка. Файлы вне репозитория.
4. **Ручной проход** — пункты 1–8 «Объёма работы» по порядку. Для пункта 4
   (в MinIO один объект) — консоль MinIO или `mc ls` по префиксу
   композиции; для пункта 8 — вкладка Network, время `POST`.
   Для пункта 9 — файл с аудиодорожкой длиннее видео (например, склеить
   `ffmpeg`-ом). Дополнительно к сценарию: после `POST` убедиться в одном (не двух)
   запросе `GET .../video`; обновить страницу во время замены (несохранённый
   файл теряется — ожидаемо).
5. **Фиксация результата.** Раздел в [status.md](../status.md) (дата,
   результаты `lint/test/build`, время обрезки самого большого файла,
   найденные и исправленные отклонения), строка этапа 9 → «выполнен»,
   колонка задач → «4 из 4»; статус задач 1–4 в [README этапа](./README.md)
   и в таблицах `status.md` — «выполнена»; ТЗ — статус этапа 9
   «выполнено» (правило 9).
6. **Ревью.** Этап целиком — `/code-review` уровня `medium` на дифф
   этапа; перед запуском спросить пользователя (запуск ревью — по его
   команде).

**Принятый риск.** Ручной проход нельзя автоматизировать в рамках этапа
(реальные файлы и MinIO): если стенд недоступен, этап остаётся открытым, а
не закрывается зелёными тестами на моке.

## Критерии готовности

- `npm run lint`, `npm run test`, `npm run build` без ошибок.
- Сценарий выше пройден на живом сервере; отклонения исправлены или
  заведены задачами.
- Этап 9 отмечен в [status.md](../status.md).
