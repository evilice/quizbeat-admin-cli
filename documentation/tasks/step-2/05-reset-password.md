## Зачем

Сброс пароля легко собрать копией формы «сменить свой»: те же 8
символов и тот же `204`, но другой путь и нет `currentPassword`. При
чужом id сессия текущего супер-админа должна остаться. Форма своего
пароля в шапке по-прежнему доступна обеим ролям. Эта задача добавляет
действие на строку списка и второй маршрут не заводит.

## Границы задачи

| Входит | Не входит |
|---|---|
| Диалог на строке: только новый пароль, `PATCH /admins/:id/password` | `PATCH /admins/me/password` и поле текущего пароля — [задача 5 этапа 1](../step-1/05-change-own-password.md) |
| Новый пароль короче 8 символов на сервер не уходит | Смена роли и деактивация — [задача 4](./04-role-and-activity.md) |
| `204` на чужой id сессию не меняет; `204` на свой id забывает refresh и оставляет access | Новая пара токенов. Этот эндпоинт её не выдаёт |

## ⚠ Технические нюансы и ограничения

- Путь собирается из id строки: `/admins/<uuid>/password`. Сегмент `me`
  в него не подставляется. Запрос на `/admins/me/password` с одним
  `newPassword` — это смена своего пароля без `currentPassword`, сервер
  ответит `400`. Разборщик этапа 1, который узнаёт `401` с текстом
  `Current password is incorrect`, здесь ни при чём: этот эндпоинт
  такой ответ не присылает.
- Тело — `{ newPassword }`. Полей `currentPassword` и `password` в нём
  нет. Текущий пароль цели эндпоинт не проверяет и `401` за него не
  отдаёт.
- Успех — `204` без тела. Разбирать ответ как объект сотрудника нельзя:
  тела нет, клиент этапа 0 возвращает `undefined`.
- Чужой id: ключ refresh и access остаются. Свой id, то есть сброс
  пароля самому себе из этой же таблицы: после `204` забывается только
  refresh, оболочка остаётся, `POST /auth/staff/refresh` не вызывается.
  Иначе клиент отправит уже отозванный токен на refresh, и перехватчик
  откроет логин при ещё живом access. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- Новый пароль короче 8 символов на сервер не отправляется. Порог — 8.
  Если всё же пришёл `400` с массивом в `message`, форма показывает
  его целиком через общий разбор ошибки.
- `404`, если такого id уже нет, показывает `message`. Диалог при этом
  не закрывается так, будто пароль сменён.
- Экран списка общий с задачами 3 и 4. Эта задача добавляет на строку
  действие «сбросить пароль». При конфликте слияния она вливается
  последней из трёх, см. [README](./README.md#почему-такой-порядок).

## Объём работы

- Действие на строке списка открывает диалог с одним полем нового
  пароля. Подписи русские. Поля текущего пароля на форме нет.
- Отправка вызывает метод стора с id этой строки. Проверка до запроса:
  пароль короче 8 символов — русское сообщение, `fetch` не вызывается.
- `204` на чужой id: диалог закрыт, по-русски подтверждено, что пароль
  задан, стор сессии не изменился. `204` на свой id: то же подтверждение,
  refresh забыт, access и оболочка на месте.
- Тесты:
  - пароль из 7 символов не вызывает `fetch`;
  - отправка шлёт `{ newPassword }` на `/admins/<id>/password` и не
    шлёт `currentPassword`; в URL нет сегмента `me`;
  - `204` для чужого id не вызывает «забыть refresh» и не шлёт
    `/auth/staff/refresh`;
  - `204` для id текущей сессии вызывает «забыть refresh», access
    остаётся.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят.
- В модуле диалога путь пароля содержит uuid сотрудника и не содержит
  `me/password`. Проверяется чтением модуля.
