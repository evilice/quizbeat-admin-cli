# Задача 2 — Первая загрузка карточки одним `GET /full`

Этап: 8 — Сборка карточки композиции.
Зависимости: [задача 1](./01-full-card-store.md); экран карточки —
[задача 4 этапа 4](../step-4/04-composition-card.md); блоки аудио /
отрезков — [этап 5](../step-5/README.md); картинок —
[этап 6](../step-6/README.md); заметок — [этап 7](../step-7/README.md).
Ссылка на ТЗ: [раздел «Этап 8»](../../03-technical-specification.md#этап-8--сборка-карточки-композиции)
(первая загрузка не делает пачку самостоятельных списков; пустые
состояния; ошибки и `404`).
Карта: `GET /compositions/:id/full` в
[композициях](../../02-staff-api.md#5-композиции).

## Зачем

К этому моменту карточка открывается стыком этапа 4 (`location.state`
или повторный `GET /compositions` по query), а блоки 5–7 на маунте ходят
за своими списками. DoD этапа 8 — один `GET /full` в сети на открытии.
Эта задача **заменяет** тот стык и убирает пачку первых `GET` блоков,
не переписывая сценарии загрузки трека, точек, DnD и формы заметок.
Обновление после мутаций — следующая задача.

## Границы задачи

| Входит | Не входит |
|---|---|
| Монтирование `/compositions/:id`: один `GET /full` (прямой заход, переход со списка, F5) | Правило обновления после мутаций — [задача 3](./03-post-mutation-refresh.md) |
| Замена стыка [задачи 4 этапа 4](../step-4/04-composition-card.md): больше не опираться на `location.state` / повторный `GET /compositions` как источник данных карточки | Новый маршрут. Восстановление удалённой композиции |
| Блоки 5–7 на маунте **не** вызывают свои `GET .../clips` / `images` / `notes` / `audio`, если полной карточки достаточно; читают данные из ответа `GET /full` | Переписывание multipart, опроса, DnD, формы заметок как новых фич |
| Пустые состояния: нет трека (`null` URL и длительности), нет отрезков / картинок / заметок (пустые массивы); пустая композиция даёт загрузить трек (UI загрузки — этап 5) | |
| Состояния `404` (нет id / мягко удалена) и ошибки сети — отдельные, не бесконечный скелет | |

## ⚠ Технические нюансы и ограничения

- Заменяемый стык описан в
  [решениях этапа 4](../step-4/README.md#решения-по-открытым-вопросам-этапа)
  и в [задаче 4 этапа 4](../step-4/04-composition-card.md): из списка —
  `location.state` + search с query списка; без state — повторный
  `GET /compositions` и поиск строки по id. Этот этап оставляет один
  способ: `GET /full`. Тесты этапа 4, которые требуют «не вызывать
  `/full`», на этом этапе **переписываются**: теперь `/full` —
  ожидаемый единственный вызов загрузки.
- `location.state` со списка **можно** показать как мгновенный заголовок
  (название / автор), пока идёт запрос, но **нельзя** брать из него
  `clips` / `images` / `notes` / URL / длительность — списка этих полей
  нет.
- `null` у `originalAudioUrl` / `originalAudioDurationSec` — пустое
  состояние «трек не загружен», блок загрузки этапа 5 доступен.
  Ограничение этапа 5 «после F5 точки не слать» этим **снимается**:
  длительность для разметки берётся из полной карточки. Длительность из
  `<audio>` не подставлять.
- Опрос `GET .../clips` **после** открытия, пока есть `PENDING` /
  `PROCESSING`, остаётся решением этапа 5: полная карточка опрос не
  отменяет. На **маунте** отдельный первый `GET .../clips` не нужен —
  список уже в `GET /full`.
- Волна: URL на открытии — из `originalAudioUrl` полной карточки, не
  отдельный `GET .../audio`. `GET .../audio` остаётся способом обновить
  протухшую ссылку и способом после `POST .../audio` (см.
  [README](./README.md#обновление-после-мутаций)), не способом первой
  загрузки.
- Первая загрузка картинок / заметок: свои `GET .../images` и
  `GET .../notes` на маунте **не** делать, если `GET /full` уже отдал
  массивы (в том числе пустые). Это заменяет решения
  [этапа 6](../step-6/README.md) и [этапа 7](../step-7/README.md) про
  «до этапа 8 список — только свой GET».
- Конфликт на файле карточки: правки вливаются **после** блоков
  этапов 5–7. Общий файл — экран `/compositions/:id`.

## Объём работы

- Карточка при монтировании (с state и без) вызывает метод
  [задачи 1](./01-full-card-store.md) с `id` из пути.
- Убрать / отключить путь «повторный `GET /compositions` + поиск в
  `items`» и использование state как источника полей формы и блоков.
- Раздать ответ блокам: форма композиции / теги; аудио (URL +
  длительность или пустое состояние); список отрезков; картинки;
  заметки.
- UI: скелет / индикатор только пока идёт первый `GET /full`; при
  `404` — «не найдена» со ссылкой на `/compositions`; при сетевой
  ошибке — сообщение и возможность повторить, не вечный скелет.
- Тесты:
  - монтирование `/compositions/:id` (с state и без) → ровно один
    `GET .../full`; нет `GET /compositions` (список), нет
    `GET .../clips`, `GET .../images`, `GET .../notes`, `GET .../audio`
    на маунте при успешном полном ответе;
  - ответ с `originalAudioUrl: null` → на экране пустое состояние трека
    и доступна загрузка (блок этапа 5), нет ошибки сессии;
  - ответ с пустыми `clips` / `images` / `notes` → пустые состояния
    блоков, не ошибка;
  - `404` на `GET /full` → состояние «не найдена», нет бесконечного
    индикатора;
  - тесты этапа 4 «не вызывать `/full`» обновлены под новое правило
    (или удалены как устаревшие).

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят: маршрут карточки тот же.
- В модуле маунта карточки нет вызова пачки списков блоков при
  успешном `GET /full`. Проверяется тестом на моке сети.
