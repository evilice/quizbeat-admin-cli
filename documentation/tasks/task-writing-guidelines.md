# Правила оформления задач разработки

Общее соглашение для всех репозиториев QuizBeat — в
[quizbeat-docs/process/task-writing-guidelines.md](https://github.com/evilice/quizbeat-docs/blob/main/process/task-writing-guidelines.md):
структура директории `step-N/`, обязательные секции файла задачи, правила
читаемости. Здесь — только то, что специфично для веб-клиента.

Номер `step-N` — номер этапа [ТЗ клиента](../03-technical-specification.md),
без сдвига. Это порядок поставки экранов клиента, не номера этапов
`quizbeat-srv`: сессия — этап 1, сотрудники — этап 2, контент начинается с
тегов на этапе 3.

## Задачи, которые ходят в API

В метаданных задачи — ссылка на раздел [staff-api.md](https://github.com/evilice/quizbeat-docs/blob/main/api/staff-api.md)
в `quizbeat-docs` и на контроллер или DTO в
`quizbeat-srv`. Поля, которые уже есть в карте, внутри задачи не
пересказываются.

## Примеры для секции «Технические нюансы и ограничения» (⚠)

Уровень детализации, который ожидается от пунктов этой секции:

- Переменные окружения Vite попадают в клиентский бандл только с префиксом
  `VITE_`. Имя без префикса молча остаётся `undefined`.
- Dev-сервер слушает порт `5173`: на это значение уже выставлен
  `CORS_ORIGIN_ADMIN` бэкенда. Смена порта без правки env сервера выглядит
  как «API не отвечает», хотя падает CORS.
- Access-токен staff содержит `sub`, `role` и `type: 'staff'`, но не email.
  Почту для шапки экрана нельзя прочитать из JWT.
- `POST /auth/staff/refresh` ротирует refresh: повторно отправить
  предыдущий токен нельзя, сервер его уже отозвал.
- `fileUrl` отрезка отсутствует в JSON, пока статус не `DONE` — это не
  `null`. Ссылка на оригинал и на картинку — presigned, TTL по умолчанию
  3600 секунд; класть её в стор как постоянный адрес нельзя.
- `GET /compositions?tagIds=` — одна строка через запятую, не повторяющийся
  query-параметр. `GET /admins?isActive=` — строки `true` / `false`.
- Multipart: исходный трек — поле `file`, картинки — поле `files` (до 10
  файлов). Путать имена — `400`, файл до сервера не доходит.
- Любой момент, где две задачи правят один и тот же файл (корневой роутер,
  HTTP-клиент, каркас стора сессии) — фиксировать ожидаемый порядок правок
  или предупреждать о конфликте.

## Критерии готовности

Способы проверки здесь — тест, ручной проход в браузере, сверка с ответом
сервера. Формулировка «экран написан» недостаточна.
