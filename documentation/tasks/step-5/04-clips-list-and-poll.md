# Задача 4 — Список отрезков и опрос статусов

Этап: 5 — Аудио и отрезки.
Зависимости: [задача 1](./01-audio-clips-store.md) (разовый
`GET .../clips`); блок на карточке из
[задачи 2](./02-audio-upload.md) (есть куда посадить список). После
отправки точек из [задачи 3](./03-waveform-and-points.md) список
обновляется, но топологически эта задача от 3 не зависит.
Ссылка на ТЗ: [раздел «Этап 5»](../../03-technical-specification.md#этап-5--аудио-и-отрезки)
(список; опрос пока есть `PENDING` / `PROCESSING`; `DONE` с `fileUrl`;
явный `FAILED`).
Карта: [аудио и отрезки](../../02-staff-api.md#6-аудио-и-отрезки).
Статусы —
[`AudioClipStatus`](../../../../quizbeat-srv/src/audio-clips/audio-clip-status.enum.ts),
ответ —
[`AudioClipResponseDto`](../../../../quizbeat-srv/src/audio-clips/dto/audio-clip-response.dto.ts).

## Зачем

Нарезка асинхронная: без опроса DoD «увидеть переход до `DONE` или
`FAILED`» не закрыть. Остановку опроса ТЗ требует покрыть тестом — её
логичнее держать на экране, а не вечным таймером в сторе. Удаление и
перегенерация — следующая задача, чтобы не смешать их с этим тестом.

## Границы задачи

| Входит | Не входит |
|---|---|
| Список отрезков на карточке: начальные данные — `clips` из ответа `full`, полученного [задачей 4 этапа 4](../step-4/04-composition-card.md); статус, старт, длительность, сложность | Разметка и `POST .../clips` — [задача 3](./03-waveform-and-points.md) |
| Опрос `GET .../clips` каждые 2 с, пока есть `PENDING` или `PROCESSING`; остановка на терминальных статусах и на пустом списке | Удаление и перегенерация в UI — [задача 5](./05-clip-delete-and-regenerate.md) |
| У `DONE` — прослушивание по `fileUrl`; у `FAILED` — явное состояние, не вечный спиннер | Подстановка `fileUrl: null` — запрещено, поле просто отсутствует до `DONE` |
| Тест: опрос прекращается, когда незавершённых статусов не осталось; на маунте блок не делает собственный первый `GET .../clips`, если `full` уже дал массив | Интервал «зашить» в стор как единственный глобальный таймер приложения |

## ⚠ Технические нюансы и ограничения

- Интервал и условие остановки —
  [README](./README.md#решения-по-открытым-вопросам-этапа): 2 с; стоп,
  если нет ни одного `PENDING`/`PROCESSING` (в том числе все `FAILED`,
  смесь `DONE`+`FAILED`, `[]`). Начальный список — `clips` из ответа
  `full`, уже полученного карточкой; собственный `GET .../clips` на
  маунте блок делает только если этих данных почему-то нет. Опрос по
  первому такому массиву запускается сразу, если в нём уже есть
  `PENDING` / `PROCESSING`.
- `fileUrl` есть в JSON только при `DONE`. Плеер не строить, если поля
  нет. Не путать с картинками этапа 6.
- После успешной отправки точек (задача 3) и после повторной загрузки
  трека (задача 2) список нужно перечитать и при необходимости снова
  запустить опрос — координация на карточке, без второго HTTP-клиента.
- `404` композиции — сообщение, не бесконечный опрос. Размонтирование
  карточки снимает таймер (нет утечки интервала).
- Presigned `fileUrl` тоже временный: для прослушивания достаточно
  текущего ответа списка; при протухании — новый `GET .../clips`, не
  вечный URL в сторе.
- Общий файл карточки: после задачи 3 при конфликте слияния, до
  задачи 5.

## Объём работы

- Блок «Отрезки» на карточке: начальные строки — из `clips` ответа
  `full`, уже сохранённого состоянием карточки; после мутаций и во время
  опроса — из `GET .../clips`.
- Пока в текущем массиве есть `PENDING` или `PROCESSING` — через 2 с
  снова вызвать метод списка стора; иначе таймер не ставить. Проверка
  делается и на начальном массиве из `full` (опрос может понадобиться
  сразу при открытии карточки).
- `DONE` — элемент `<audio>` (или эквивалент) с `fileUrl`.
- `FAILED` — русская подпись конечного отказа, без спиннера «ещё
  режется».
- Тесты (fake timers / мок `fetch`):
  - блок не делает собственный `GET .../clips` на маунте, если в
    состоянии карточки уже есть массив `clips` (в том числе пустой) из
    `full`;
  - при начальном массиве с `PENDING` опрос стартует сразу;
  - при ответе с `PENDING` планируется следующий `GET .../clips`;
  - при ответе только с `DONE` и/или `FAILED` (и при `[]`) следующего
    запроса по таймеру нет;
  - в строке не-`DONE` UI не обращается к `fileUrl`;
  - размонтирование очищает интервал (нет лишнего `fetch` после unmount).

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test` — в том числе
  тест остановки опроса, которого требует DoD этапа.
- `npm run lint` проходит.
- Ручной ориентир: после создания точек статусы на экране сменяются без
  перезагрузки страницы, пока сервер не вернёт терминальные; полный
  проход с реальным файлом — у [приёмки](./06-step5-acceptance.md).
