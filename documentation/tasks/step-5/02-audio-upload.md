## Зачем

Без загруженного трека нет `originalAudioDurationSec`, которым
ограничивать разметку точек — ни в ответе `full` (там будет `null`), ни
после загрузки (см.
[решения этапа](./README.md#решения-по-открытым-вопросам-этапа)). Блок на
существующей карточке фиксирует поле `file`, подсказку типов и показ
отказа API до волны и списка. Волну и опрос сюда не тащить: иначе тест
multipart смешается с библиотекой и таймером.

## Границы задачи

| Входит | Не входит |
|---|---|
| Блок загрузки на `/compositions/:id`: выбор файла, подсказка mp3 / wav / flac и ориентир 200 МБ, вызов метода стора | Волновая форма и разметка точек — [задача 3](./03-waveform-and-points.md) |
| После `201` — обновить `originalAudioDurationSec` в состоянии карточки для последующей разметки | Список отрезков и опрос — [задача 4](./04-clips-list-and-poll.md) |
| Состояние «трек загружен / не загружен» при первом открытии — из `originalAudioUrl` / `originalAudioDurationSec` ответа `full`, который уже получила [задача 4 этапа 4](../step-4/04-composition-card.md); показ `message` при `400` / `413` / `415` / `422` | Собственный запрос за `originalAudioUrl` при первом открытии — карточка уже его получила |
| | Картинки (`files`) — [этап 6](../../03-technical-specification.md#этап-6--изображения-композиции) |

## ⚠ Технические нюансы и ограничения

- Имя поля — `file`. Клиентская подсказка расширений не заменяет
  проверку по содержимому на сервере. Отказ — `message` как пришёл.
- Длительность для разметки при первом открытии карточки (включая F5) —
  `originalAudioDurationSec` из ответа `GET .../full`, который уже
  получила [задача 4 этапа 4](../step-4/04-composition-card.md); сразу
  после успешной загрузки — из тела `201`, не из `HTMLAudioElement`.
  Ограничения «нет длительности после F5» больше нет.
- Повторная загрузка заменяет оригинал на сервере, отрезки не трогает.
  После успеха — обновить длительность из ответа; список отрезков
  перечитает [задача 4](./04-clips-list-and-poll.md) / экран при
  наличии. Подтверждение «заменить трек?» — по желанию UI; сервер
  отдельного флага замены не требует.
- «Трек не загружен» при первом открытии — это `originalAudioUrl: null`
  в ответе `full`, не `404`. Собственный `GET .../audio` этот блок на
  маунте не делает; такой запрос нужен только для обновления уже
  известной, но протухшей ссылки (после `POST .../audio` или по TTL).
  `404` на нём (если он всё же вызван) — сообщение блока, не выход из
  сессии.
- Текст подсказок и ошибок — React-текст, без
  `dangerouslySetInnerHTML`. Загрузка файлов — категория обязательного
  человеческого ревью (поле multipart и обещания про тип/размер), см.
  [README](./README.md).
- Общий файл — карточка этапа 4. При конфликте слияния с задачами 3–5 —
  эта задача вливается первой после стора, см.
  [порядок](./README.md#почему-такой-порядок).

## Объём работы

- На карточке композиции — блок «Исходный трек»: input файла (или
  эквивалент MUI), русская подсказка допустимых типов и ориентира
  размера, кнопка загрузки.
- Состояние блока при появлении на экране читается из уже полученного
  ответа `full`: `originalAudioUrl !== null` значит трек есть (URL
  волне передаст задача 3); `null` — пустое состояние загрузки. Блок
  сам `GET .../audio` на маунте не вызывает.
- Успех `201`: показать, что трек принят; обновить
  `originalAudioDurationSec` (и сбросить прежний `originalAudioUrl`) в
  состоянии карточки для задачи 3.
- Отказы API показать на блоке без очистки сессии.
- Тесты:
  - выбор файла и отправка вызывают стор / `fetch` с полем `file`;
  - при `201` в состоянии экрана оказывается `originalAudioDurationSec`
    из тела ответа;
  - `415` / `413` / `400` с `file is required` показывают `message`;
  - `originalAudioUrl: null` в данных карточки даёт состояние «трек не
    загружен», без собственного запроса `GET .../audio` и без редиректа
    на логин;
  - блок не делает вызов пути `/full` сам — использует данные, уже
    переданные карточкой.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` проходит.
- Ручной проход: на карточке можно выбрать mp3/wav/flac и увидеть либо
  успех с длительностью в UI/состоянии, либо `message` сервера. Проверка
  против запущенного `quizbeat-srv` или против мока с тем же телом
  `201` — достаточно для этой задачи; полный DoD с нарезкой — у
  [приёмки](./06-step5-acceptance.md).
