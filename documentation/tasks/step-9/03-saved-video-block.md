# Задача 3 — Блок на карточке: сохранённое видео, замена, удаление

Этап: 9 — Видео композиции.
Зависимости: [задача 2](./02-video-trim-editor.md); удаление с
подтверждением — [задача 4 этапа 6](../step-6/04-images-delete.md).
Ссылка на ТЗ: [раздел «Этап 9»](../../03-technical-specification.md#этап-9--видео-композиции).

## Зачем

После сохранения нужно видеть, что именно лежит на сервере, и уметь
заменить или удалить. Отдельно от редактора: другой источник данных
(`videoUrl` с сервера, а не локальный файл) и другие правила обновления
(протухающая presigned-ссылка).

## Границы задачи

| Входит | Не входит |
|---|---|
| Блок «Видео»: если видео есть — `<video controls preload="metadata">` по `videoUrl`, длительность; если нет — пустое состояние с редактором из задачи 2 | Правка границ сохранённого видео — исходника нет |
| «Заменить»: подтверждение, затем тот же редактор; пока замена не сохранена, на сервере прежнее видео | Несколько видео |
| «Удалить»: подтверждение, `DELETE`, возврат в пустое состояние | Игровой клиент |
| Обновление ссылки при ошибке плеера | — |

## ⚠ Технические нюансы и ограничения

- Presigned-URL в `src` протухает: при `error` у `<video>` один раз
  перезапросить `GET .../video` и подставить новый URL; не зацикливать.
- Текст подтверждения замены/удаления явно говорит: «исходный файл не
  хранится, вернуть прежнее видео или изменить его границы будет
  нельзя».
- Отмена замены не должна менять сохранённое видео и его `videoUrl`.
- Текст с сервера рендерится как текст, без `dangerouslySetInnerHTML`.
- Видео не влияет на публикацию; блок доступен и для `DRAFT`, и для
  `PUBLISHED`.

## Объём работы

- `SavedVideoBlock.tsx` + тесты; подключение в `CompositionCardTabs.tsx`
  вместе с редактором задачи 2.

## План работы

Порядок — от обновления данных карточки к блоку, затем к подтверждениям;
тест до кода каждого шага. `npm run lint` и `npm run test` — после каждого
шага (правило 8), `npm run build` — в конце (задача меняет хук карточки и
вкладки). Новых зависимостей нет.

**Шаги.**

1. **Разведка (сделана, повторить при реализации).**
   - Источник правды по видео — `full` в `use-composition-card.ts`
     (`videoUrl`, `videoDurationSec`); сторы данных не хранят (см.
     [задачу 1](./01-video-store.md)). Образец обновления после мутации —
     `handleAudioUploaded` (правка `full` через `setFull`).
   - Образец подтверждения удаления с ошибкой **внутри диалога**,
     сбросом ошибки отменой и блокировкой при `busy` — `ImagesBlock`
     (`deleteTarget`, `closeDelete`, `confirmDelete`, `ErrorMessages` в
     `DialogContent`); ошибки удаления на экране под диалогом не
     дублируются.
   - Образец тротлинга обновления протухшей ссылки —
     `useAttemptThrottle(URL_REFRESH_INTERVAL_MS)` (`ImagesBlock`,
     `ClipsListBlock`): «ровно один повторный `GET`» из критериев — это
     ключ по `compositionId` + версия видео, а не глобальный счётчик.
2. **Хук карточки (TDD).** В `use-composition-card.ts`:
   - `handleVideoSaved(durationSec)` — `videoDurationSec = durationSec`,
     `videoUrl = null` (старая ссылка сброшена **до** запроса новой, иначе
     плеер на миг покажет прежнее видео), `videoVersion += 1`;
   - `handleVideoRemoved()` — оба поля `null`, `videoVersion += 1`;
   - `handleVideoUrl(url)` — подстановка свежей ссылки из `GET`.
   Вернуть из хука; тесты — в `CompositionCard.test.tsx`.
3. **Блок `video/SavedVideoBlock.tsx` + хук `video/use-saved-video.ts`
   (TDD).**
   - После `handleVideoSaved` блок видит `videoUrl === null &&
     videoDurationSec !== null` → эффект запрашивает `video.getUrl(id)` и
     отдаёт ссылку через `handleVideoUrl`; `404` → видео нет (оба поля
     `null`); эффект защищён от устаревшего ответа (`cancelled`-флаг, как в
     загрузке `full`) — быстрая замена не должна показать ссылку прежней
     версии.
   - `videoUrl !== null` → `<video controls preload="metadata" src>` и
     длительность («Длительность: N с»); `videoUrl === null &&
     videoDurationSec === null` → пустое состояние + `VideoTrimEditor`
     (задача 2).
   - `error` у `<video>` → `mayRefreshUrl(id)`; если разрешено — один
     `getUrl`, подстановка; иначе (или повторная ошибка) — текст «Не
     удалось воспроизвести видео» без цикла.
4. **Замена.** Кнопка «Заменить видео» → `Dialog` с текстом «Исходный файл
   не хранится: вернуть прежнее видео или изменить его границы будет
   нельзя» → «Продолжить» раскрывает `VideoTrimEditor` под плеером
   (локальное состояние `replacing`), «Отмена» не трогает `full`.
   Прежнее видео остаётся на сервере и в `full`, пока `save` не вернул
   успех; успех → `handleVideoSaved` + `replacing = false`. Ошибка `save`
   не сбрасывает `replacing` и не трогает прежний плеер.
5. **Удаление.** «Удалить видео» → диалог по образцу `ImagesBlock`; текст
   тот же про необратимость; `confirm` → `video.remove(id)` → успех:
   `handleVideoRemoved`, диалог закрыт; ошибка — в диалоге, видео в
   `full` на месте. `404` на `DELETE` композиции — как у картинок:
   сообщение в диалоге.
6. **Подключение во вкладку «Видео»** (заведена задачей 2): блок целиком
   заменяет прямой рендер редактора; `active={tab === 'video'}` передаётся
   в плеер и редактор — при уходе с вкладки обоим `pause()` (панели
   остаются смонтированными).
7. **Ревью.** `/code-review` уровня `medium`, отдельный контекст. Для
   человека: необратимость замены/удаления в тексте диалога, отсутствие
   `dangerouslySetInnerHTML`, нет гонки «ссылка прежней версии после
   замены».

**Принятый риск.** Между «Сохранить» и ответом `GET .../video` блок
показывает короткое состояние «получаем ссылку» без плеера — осознанно,
вместо показа прежней (уже удалённой на сервере) ссылки.

## Критерии готовности

- `npm run test`, `npm run lint`, `npm run build` проходят.
- Тесты на моке: `videoUrl: null` — виден редактор, плеера нет; `videoUrl`
  есть — плеер с этим `src` и длительностью; замена требует
  подтверждения, отмена оставляет прежнее видео; после успешного
  сохранения `src` — из нового `GET .../video`, не прежний; удаление
  требует подтверждения, вызывает `DELETE`, возвращает пустое состояние;
  при `error` плеера выполняется ровно один повторный `GET .../video`.
