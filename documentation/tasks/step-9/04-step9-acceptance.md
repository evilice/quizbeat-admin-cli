# Задача 4 — Приёмка этапа 9

Этап: 9 — Видео композиции.
Зависимости: [задача 3](./03-saved-video-block.md) (и транзитивно
задачи 1–2); серверный этап 14 в `main`.
Ссылка на ТЗ: [DoD раздела «Этап 9»](../../03-technical-specification.md#этап-9--видео-композиции).

## Зачем

Тесты на моке не ловят стык с реальным сервером: имена полей multipart,
дробные секунды, время синхронной обрезки большого файла, реальное
воспроизведение результата браузером, отсутствие исходника на сервере.
Новой функциональности нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` с реальными mp4 и webm | Игровой клиент |
| Исправление стыка, если задачи 1–3 не складываются в DoD | Новые поля и экраны |

## Объём работы

Ручной проход в браузере:
1. Выбрать mp4 (несколько десятков МБ) → играет локально, длительность
   верна. Выбрать отрезок с дробными границами (например 1.5–6.0 с),
   проиграть его → сохранить.
2. После сохранения виден плеер с результатом: длительность ≈ 4.5 с,
   проигрывается именно выбранный фрагмент (сверить по содержимому).
3. F5 → видео на месте (из `GET /full`).
4. В MinIO для композиции ровно один объект видео, исходника нет
   (проверить по содержимому бакета).
5. Заменить файлом webm с другим отрезком → играет новый, прежний
   объект в MinIO удалён.
6. Файл mp3 вместо видео и отрезок длиннее максимума → понятные
   ошибки, прежнее видео не пострадало.
7. Удалить → пустое состояние, повторный `GET /full` даёт `null`.
8. Время ответа обрезки на самом большом реалистичном файле — записать
   в итог.

Результат записать в [status.md](../status.md).

## Критерии готовности

- `npm run lint`, `npm run test`, `npm run build` без ошибок.
- Сценарий выше пройден на живом сервере; отклонения исправлены или
  заведены задачами.
- Этап 9 отмечен в [status.md](../status.md).
