# Задача 2 — Выбор файла, предпросмотр, выбор отрезка и отправка

Этап: 9 — Видео композиции.
Зависимости: [задача 1](./01-video-store.md); образец разметки по
времени — [задача 3 этапа 5](../step-5/03-waveform-and-points.md),
загрузка файла — [задача 2 этапа 5](../step-5/02-audio-upload.md).
Ссылка на ТЗ: [раздел «Этап 9»](../../03-technical-specification.md#этап-9--видео-композиции).

## Зачем

Главный сценарий этапа: контент-менеджер выбирает файл, смотрит его,
отмечает нужный фрагмент и сохраняет только его. Выделен отдельно от
блока сохранённого видео (задача 3): здесь вся локальная логика
(object URL, плеер, границы), там — работа с тем, что уже на сервере.

## Границы задачи

| Входит | Не входит |
|---|---|
| Скрытый file input (`accept` mp4/webm), подсказка «mp4, webm, до 500 МБ» | Показ уже сохранённого видео, удаление — [задача 3](./03-saved-video-block.md) |
| Локальный предпросмотр `<video controls>` по `URL.createObjectURL(file)` | Волновая форма видео, покадровая лента |
| Выбор отрезка: двойной `Slider` по длительности из `loadedmetadata`, поля начала/конца, кнопки «начало = текущая позиция» / «конец = текущая позиция», кнопка «проиграть выбранный отрезок» | Прогресс-бар загрузки |
| Клиентские проверки: `start < end`, длина ≤ максимума, `end ≤ длительность`; кнопка «Сохранить» → `save()` | Серверные правила — остаются на сервере |
| Блокировка во время отправки, показ ошибок сервера | — |

## ⚠ Технические нюансы и ограничения

- **Утечка object URL:** `revokeObjectURL` при смене файла,
  отмене и размонтировании; тест на вызов.
- **Воспроизведение выбранного отрезка:** по `timeupdate` останавливать
  на `endSec` (событие приходит с шагом ~250 мс — допускается небольшой
  выход за границу при предпросмотре, обрезка на сервере точная);
  при старте — `currentTime = startSec`.
- **Файл не проигрывается браузером** (`error` у `<video>` или нет
  `loadedmetadata`) — «Сохранить» заблокировано, текст «Не удалось
  прочитать видео; нужен mp4 или webm».
- Состояние редактора (файл, `startSec`, `endSec`) не хранится в
  `localStorage` и не переживает уход со страницы — файл большой,
  предупреждение при уходе во время отправки не обязательно.
- Числа `startSec`/`endSec` округлять до 2 знаков (сервер принимает
  дробные; больше точности ползунку не нужно).
- Константа макс. длины отрезка (60 с) — одна, рядом с блоком, комментарий
  со ссылкой на серверную `VIDEO_MAX_CLIP_DURATION_SEC`.
- Размещение и разрез файлов — раздел 11
  [правил разработки](../../04-development-rules.md): разметка отдельно
  от сценария, в `src/modules/compositions/video/`.

## Объём работы

- `VideoTrimEditor.tsx` (+ хук `use-video-trim.ts` для состояния
  границ и object URL) и тесты рядом.
- Подключение на карточке (вкладка/секция «Видео»).

## Критерии готовности

- `npm run test`, `npm run lint`, `npm run build` проходят.
- Тесты на моке (jsdom, `HTMLMediaElement` замокан): выбор файла
  показывает плеер с object URL и подсказку; после `loadedmetadata`
  ползунок охватывает `0…duration`, значения по умолчанию — от начала до
  min(длительность, максимум); невалидные границы блокируют «Сохранить»
  с причиной; «Сохранить» вызывает `save(file, start, end)` ровно с
  выбранными значениями; во время отправки input, ползунок и кнопка
  заблокированы; ошибка `400/413/415` показывается; смена файла и
  размонтирование вызывают `revokeObjectURL`; ошибка `<video>`
  блокирует отправку.
