# Задача 4 — Приёмка этапа 8

Этап: 8 — Сборка карточки композиции.
Зависимости: [задача 3](./03-post-mutation-refresh.md) (и транзитивно
первая загрузка из [задачи 2](./02-card-first-load.md) и стор из
[задачи 1](./01-full-card-store.md)).
Ссылка на ТЗ: [DoD раздела «Этап 8»](../../03-technical-specification.md#этап-8--сборка-карточки-композиции).

## Зачем

Задачи 1–3 по отдельности закрывают контракт и стык на моке. DoD
этапа — другой контур: на живом `quizbeat-srv` карточка открывается
одним `GET /full`, блоки этапов 5–7 по-прежнему выполняют свой
сценарий, пустая композиция читается и даёт загрузить трек, `404` —
отдельное состояние. Без сервера стык легко остаётся зелёным в тестах
при пачке списков на маунте. Новой функциональности здесь нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| Прогон `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` | Новые поля форм, новый маршрут, игрок, восстановление композиции |
| Исправление стыка, если задачи 1–3 не складываются в DoD: пачка `GET` на открытии, смешение `fileUrl`, `404` как скелет, пустая композиция без загрузки трека | Переписывание multipart / опроса / DnD / формы заметок сверх стыка этапа 8 |
| Проверка тестов стора `GET /full` и тестов «частичный POST images не затирает» / «PATCH не обнуляет clips» в общем `npm run test` | Подмена порта 5173 или базового URL |
| | Смена маршрута `/compositions/:id` |

## ⚠ Технические нюансы и ограничения

- Сид `SUPER_ADMIN` — при старте сервера вне `NODE_ENV=test` и с env
  сида. Пароли в этот репозиторий не копируются. Учётка `ADMIN` тоже
  подходит: обе роли ведут композиции.
- Клиент — `http://localhost:5173`, рядом `quizbeat-srv`. Для проверки
  аудио и картинок нужно MinIO (как на приёмках этапов 5–6).
- В сети **на открытии** карточки — один `GET /compositions/:id/full`.
  Нет пачки `GET .../clips` + `GET .../images` + `GET .../notes` +
  `GET .../audio` в момент первого рендера успешной карточки. Опрос
  `GET .../clips` **после** отправки точек (пока есть `PENDING` /
  `PROCESSING`) — ожидаем, это не нарушение DoD открытия.
- После загрузки картинок в сети должен появиться `GET .../images`
  (или согласованный полный набор), а не подмена списка телом `POST`.
- `npm run test` — один прогон по `src/`: должны быть видны тест
  одного `GET /full` и тесты стыка мутаций из задачи 3. Отдельный
  «только приёмочный» набор DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–3. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест одного вызова `/full` на открытии
  (или стора) и тесты: частичный `POST .../images` не затирает уже
  показанные; `PATCH` композиции не обнуляет `clips`
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  (и MinIO, если проверяются файлы)
- Вход staff → композиции → открыть существующую карточку (со списка и
  прямым URL / F5). В сети на открытии — **один**
  `GET .../compositions/:id/full`; нет пачки списков блоков на маунте
- Пустая / свежая композиция без файлов: карточка читается; видны
  пустые состояния; можно загрузить трек (сценарий этапа 5)
- Композиция с треком, отрезками, картинками, заметками: блоки
  показывают данные из `GET /full`; сценарии этапов 5–7 (загрузка /
  точки / опрос / DnD / форма заметок) по-прежнему выполняются
- Открыть заведомо несуществующий или мягко удалённый id —
  состояние «не найдена» / ошибка `404`, не бесконечный скелет и не
  пустая форма с загрузкой трека

Композиции и файлы, заведённые только для прохода, в конце имеет смысл
убрать с экрана, если они больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Открытие одним `GET /full`, пустая композиция, `404` и
  сценарии блоков 5–7 — ручным проходом в браузере против запущенного
  `quizbeat-srv`, не только моком.
- В `npm run test` нет `.skip` на тесте одного `/full` и на тестах
  стыка мутаций из задачи 3. Проверяется тем же прогоном.
