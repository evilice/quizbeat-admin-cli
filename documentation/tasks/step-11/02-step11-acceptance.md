# Задача 2 — Приёмка этапа 11

Этап: 11 — Очистка хранилища.
Зависимости: [задача 1](./01-storage-sweep-page.md); серверный этап 16 в
`main`.
Ссылка на ТЗ: [DoD раздела «Этап 11»](../../03-technical-specification.md#этап-11--очистка-хранилища).

## Зачем

Сверка клиента с реальным ответом сервера и проверка необратимого сценария на
живых данных. Новой функциональности нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| `lint`, `test`, `build` и ручной проход против `quizbeat-srv` с включённым этапом 16 | Игровой клиент |
| Исправление стыка, если форма ответа расходится с сервером | Новые поля и экраны |

## ⚠ Технические нюансы и ограничения

- Проход делать на **локальном стеке с тестовыми данными**, не на боевом:
  удаление необратимо.
- Для «старого» сироты нужен объект старше защитного интервала сервера (1 час):
  положить его в MinIO заранее или подождать; свежий сирота при этом остаётся.

## Объём работы

Ручной проход: подготовить в MinIO старого сироту, свежего сироту и композицию
с файлами, затем удалить её. Под `SUPER_ADMIN`: «Проверить» показывает
кандидатов (старый сирота и файлы удалённой композиции, свежего нет) без
удаления; «Удалить» с подтверждением удаляет их, итог совпадает с
консолью MinIO по числу и объёму, живая композиция воспроизводится. Под
`ADMIN`: пункта меню нет, `/storage` недоступен. Результат записать в
[status.md](../status.md).

## Критерии готовности

- `npm run lint`, `npm run test`, `npm run build` без ошибок.
- Сценарий выше пройден на живом сервере; число и объём в итоге совпадают с MinIO.
- Этап 11 отмечен в [status.md](../status.md).
