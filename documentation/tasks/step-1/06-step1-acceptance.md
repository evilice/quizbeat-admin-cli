# Задача 6 — Приёмка этапа 1

Этап: 1 — Сессия сотрудника.
Зависимости: [задача 4](./04-role-menu.md) и
[задача 5](./05-change-own-password.md) (и транзитивно
[задача 2](./02-refresh-on-401.md) с тестом ротации и
[задача 3](./03-login-logout.md) с экраном входа).
Ссылка на ТЗ: [DoD раздела «Этап 1»](../../03-technical-specification.md#этап-1--сессия-сотрудника).

## Зачем

Задачи 2–5 закрывают свои моки по отдельности. DoD этапа — другой
контур: учётная запись, которая реально есть на `quizbeat-srv`,
перезагрузка вкладки, выход и сообщение неверного пароля. Стык легко
ломается так, что тесты зелёные, а живой refresh после перезагрузки
уходит старым токеном или логин обходит клиент. Новой функциональности
здесь нет.

## Границы задачи

| Входит | Не входит |
|---|---|
| Прогон `lint`, `test`, `build` и ручной проход против запущенного `quizbeat-srv` | Новые экраны, список сотрудников, запрос `GET /admins` — [этап 2](../../03-technical-specification.md#этап-2--сотрудники) |
| Исправление стыка, если задачи 1–5 не складываются в DoD (два refresh на старте, логин мимо стора, поля пароля короче 8 всё же уходят) | Подмена порта 5173 или базового URL, чтобы «открылось». Порт зафиксирован в [задаче 1 этапа 0](../step-0/01-project-scaffold.md) |
| | Ручной прогон лимита из 5 неверных логинов. `429` закрыт тестом задачи 2; выбивать лимит на общей учётке сида не нужно |

## ⚠ Технические нюансы и ограничения

- Сид `SUPER_ADMIN` создаётся при старте `quizbeat-srv`, только если
  `NODE_ENV` не `test` и в env сервера заданы `SUPER_ADMIN_EMAIL` и
  `SUPER_ADMIN_PASSWORD`. Приёмка против сервера с `NODE_ENV=test`
  логином сида не подтверждается: автосид там выключен. Пароль сида в
  этот репозиторий не копируется.
- Клиент открывается на `http://localhost:5173`. Если порт занят,
  `strictPort` роняет dev-сервер. Переносить порт нельзя: origin
  прописан в `CORS_ORIGIN_ADMIN`.
- В сетевой панели у логина один `POST /auth/staff/login` без заголовка
  `Authorization`. После перезагрузки — один `POST /auth/staff/refresh`,
  не два: восстановление и перехватчик делят promise задачи 2. Два
  refresh подряд на одной загрузке означают, что старый токен ушёл
  повторно и второй ответ будет `401`.
- После успешной смены пароля перезагрузка обязана показать логин.
  Сервер уже отозвал refresh. Если перезагрузка молча восстанавливает
  сессию, клиент где-то сохранил старый refresh или получил пару, которой
  этот эндпоинт не выдаёт.
- Видимость пункта под ролью `ADMIN` на живом сервере не проверяется:
  второй учётки ещё нет, её заводит этап 2. Достаточно теста задачи 4
  в общем прогоне. Под сидом пункт «Сотрудники» виден, заглушка
  `/admins` в сеть не ходит.
- `npm run test` гоняется один раз по всему `src/`. В выводе должен быть
  тест пачки параллельных `401` из задачи 2. Отдельный прогон «только
  приёмочных» DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–5. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест одного refresh на пачку `401` и
  тест, что старый refresh после успеха не отправляется
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
  с сидом супер-админа
- Неверный пароль на форме показывает `Invalid credentials`, оболочка
  не открывается
- Вход сидом открывает оболочку: в шапке email сида, есть выход, есть
  «Сотрудники», есть «Сменить пароль»
- Перезагрузка оставляет оболочку; в сети один `POST /auth/staff/refresh`
- Выход возвращает логин; следующая перезагрузка логин и показывает,
  нового refresh в сети нет
- Смена своего пароля на новый не короче 8 символов: текущая вкладка
  остаётся в оболочке; перезагрузка показывает логин; старый пароль
  получает `Invalid credentials`; новый пароль входит
- Заглушка «Сотрудники» не делает запроса к `/admins`
- Короткий новый пароль (7 символов) запрос смены не шлёт

После прохода пароль сида имеет смысл вернуть к значению из env
сервера тем же экраном, иначе следующий прогон войдёт уже не тем
паролем, который записан в `.env` бэкенда.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Вход, перезагрузка, выход и смена пароля — ручным
  проходом в браузере против запущенного `quizbeat-srv`, не только моком.
- В `npm run test` нет `.skip` на тестах сессии, ротации и пункта меню.
  Проверяется тем же прогоном.
