# Задача 6 — Приёмка этапа 5

Этап: 5 — Аудио и отрезки.
Зависимости: [задача 3](./03-waveform-and-points.md),
[задача 4](./04-clips-list-and-poll.md) и
[задача 5](./05-clip-delete-and-regenerate.md) (и транзитивно загрузка из
[задачи 2](./02-audio-upload.md) и стор из
[задачи 1](./01-audio-clips-store.md)).
Ссылка на ТЗ: [DoD раздела «Этап 5»](../../03-technical-specification.md#этап-5--аудио-и-отрезки).

## Зачем

Задачи 1–5 по отдельности закрывают форму запроса и опрос на моке. DoD
этапа — другой контур: на живом `quizbeat-srv` с реальным аудиофайлом
можно загрузить трек, отметить точки, увидеть переход статусов до
`DONE` или `FAILED`, прослушать отрезок, удалить и запустить
перегенерацию. Нарезка асинхронная — без сервера и файла стык легко
остаётся зелёным в тестах при вечном опросе или поле `files`. Новой
функциональности здесь нет.

## ⚠ Технические нюансы и ограничения

- Условия сида `SUPER_ADMIN`, учётки `ADMIN` и порта dev-сервера — общие
  для всех этапов, см. [acceptance-preconditions.md](../acceptance-preconditions.md).
  Учётка `ADMIN` тоже подходит: обе роли ведут аудио.
- Рядом с `quizbeat-srv` нужны рабочие MinIO/ffmpeg/очередь нарезки. Без
  воркера нарезки статусы могут застрять в `PENDING` — это среда
  сервера, не повод менять способ загрузки.
- В сети загрузки — multipart с полем `file`, ответ `201` с
  `originalAudioDurationSec`. В сети создания отрезков — JSON
  `{ points: [...] }`. В сети карточки при открытии — ровно один
  `GET .../full`, из него же блок берёт начальные `clips` и
  `originalAudioUrl` / `originalAudioDurationSec`, без отдельных
  `GET .../audio` или `GET .../clips` на маунте.
- После F5 разметка новых точек доступна сразу: длительность приходит
  из того же `GET .../full`, что открывает карточку. Отдельной загрузки
  трека для этого не требуется.
- `npm run test` — один прогон по `src/`: должны быть видны тест поля
  `file` / `points` и тест остановки опроса. Отдельный «только
  приёмочный» набор DoD не закрывает.

## Объём работы

Чек-лист на дереве, где уже есть задачи 1–5. Кода сверх них не
добавлять. Если пункт не сходится — правится стык в файлах той задачи,
которая его сломала.

- `npm run lint`
- `npm run test` — в выводе есть тест сборки `points` (целое
  `startTimeSec`, допустимые `durationSec`) и тест, что опрос не
  планирует следующий `GET`, когда нет `PENDING`/`PROCESSING`
- `npm run build`
- `npm run dev` на `http://localhost:5173`, рядом запущен `quizbeat-srv`
- Вход staff → композиции → карточка существующей или новой композиции.
  В сети при открытии карточки — ровно один `GET .../full`, нет
  отдельных `GET .../audio` или `GET .../clips` на маунте
- Загрузка реального файла (mp3, wav или flac, разумный размер): в сети
  `POST .../audio` с полем `file`, `201` и `originalAudioDurationSec`;
  на экране доступна разметка
- Разметить хотя бы одну точку внутри длительности, отправить: в сети
  `POST .../clips` с `{ points: [...] }`; в списке появляются строки
  `PENDING`/`PROCESSING`, опрос идёт; дождаться `DONE` или `FAILED`
  без перезагрузки. При `DONE` — прослушать по `fileUrl`. При `FAILED`
  — явное состояние, опрос остановился
- Удаление одного отрезка: подтверждение, в сети `DELETE` и `204`,
  строки нет после обновления списка
- Перегенерация оставшегося или другого `DONE`/`FAILED`: в сети
  `POST .../regenerate`, статус снова `PENDING`, опрос возобновляется
  до терминального статуса
- (Опционально в том же проходе.) F5 на карточке с уже загруженным
  треком: разметка новых точек доступна сразу, без повторной загрузки
  трека; волна и список отрезков видны из того же `GET .../full`

Композиции и отрезки, заведённые только для прохода, в конце имеет
смысл удалить с экрана, если они больше не нужны.

## Критерии готовности

- Все пункты чек-листа выполнены на одном рабочем дереве. Команды — по
  коду возврата. Загрузка, разметка, смена статусов, прослушивание,
  удаление и перегенерация — ручным проходом в браузере против
  запущенного `quizbeat-srv` с реальным файлом, не только моком.
- В `npm run test` нет `.skip` на тесте `points`, на тесте остановки
  опроса, на тесте поля `file` и на тесте `204` удаления. Проверяется
  тем же прогоном.
