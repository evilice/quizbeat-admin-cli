# Задача 3 — Экран логина, восстановление сессии и выход

Этап: 1 — Сессия сотрудника.
Зависимости: [задача 2](./02-refresh-on-401.md) (логин, восстановление,
выход, перехватчик `401`).
Ссылка на ТЗ: [раздел «Этап 1»](../../03-technical-specification.md#этап-1--сессия-сотрудника)
(форма, выход, восстановление при загрузке, показ `429` на логине).
Карта: [сессия](../../02-staff-api.md#2-сессия). DTO логина —
[`StaffLoginDto`](../../../../quizbeat-srv/src/staff-auth/dto/staff-login.dto.ts).
Поля тел в карте уже есть.

## Зачем

К этому моменту стор уже умеет войти, восстановиться и выйти, но
пользователь этого не видит, а при загрузке страницы восстановление
никто не вызывает. Задача ставит вызовы на маршруты и в шапку. Свою
ротацию она не пишет: иначе пачка `401` из задачи 2 и старт страницы
разойдутся на два refresh.

## Границы задачи

| Входит | Не входит |
|---|---|
| Форма email и пароля, сообщение сервера при неверном пароле, показ `429` без повтора | Реализация refresh и разбор пачки `401` — [задача 2](./02-refresh-on-401.md), здесь только вызов её метода при старте |
| После входа — прежняя оболочка, в шапке email и выход | Пункт «Сотрудники» и заглушка `/admins` — [задача 4](./04-role-menu.md) |
| Восстановление при загрузке, если в хранилище есть refresh | Форма смены своего пароля — [задача 5](./05-change-own-password.md). Ссылка в шапке появится там; здесь шапка — email и выход |
| Правка теста оболочки этапа 0 под экран логина | Список сотрудников, теги, композиции |

## ⚠ Технические нюансы и ограничения

- Тест [задачи 3 этапа 0](../step-0/03-app-shell.md) ждёт, что на `/` нет
  полей email и пароля. Теперь без сессии `/` — это логин, и поля там
  есть. Тест переписывается в этой задаче: заголовок «Админка QuizBeat»
  по-прежнему виден, кнопки выхода без сессии нет, поля логина есть.
  `.skip` на старом тесте — не сдача задачи.
- Пока идёт восстановление, логин не показывается. Иначе при живом
  refresh кадр формы мигает до ответа, и ручной проход «перезагрузка
  оставляет в сессии» выглядит как вспышка логина. Отдельного спиннера
  библиотеки не требуется: достаточно не монтировать форму, пока promise
  восстановления не завершился.
- `401` на восстановлении (негодный или уже отозванный refresh) ведёт на
  логин без баннера с текстом сервера. Этот `401` — нормальный исход
  протухшей сессии при открытии вкладки, не ошибка, которую человек
  только что совершил. `429` и сеть при восстановлении refresh не
  стирают (это делает задача 2) и оставляют человека на логине с
  сообщением: сервер недоступен или прислал `message`. Следующая
  загрузка пробует тот же refresh ещё раз.
- Неверный пароль показывает `message` разобранной ошибки как текст
  React. Для логина это строка `Invalid credentials` — одна и та же при
  неизвестном email, неверном пароле и деактивированном сотруднике.
  Своя русская подмена этой строки не пишется. `429` показывает свой
  `message` тем же путём. У установленного `@nestjs/throttler` это
  `ThrottlerException: Too Many Requests`. Кнопку «войти» не дёргать
  повторно из кода после `429`.
- Email перед отправкой и перед записью в стор нормализуется так же, как
  сервер: `trim` и нижний регистр
  ([`normalizeEmail`](../../../../quizbeat-srv/src/validation/normalize-email.ts)).
  Иначе шапка показывает `A@B.c`, а учётная запись на сервере — `a@b.c`.
  Пустая строка после `trim` не уходит запросом.
- Выход вызывает метод задачи 2 и не чистит `localStorage` из компонента.
  Компонент, который удалит ключ сам и параллельно вызовет стор, при
  гонке оставит refresh или сотрёт его до отправки logout.
- Мок успешного логина обязан вернуть access из трёх сегментов, который
  разбирает задача 1: `type: 'staff'`, непустой `sub`, роль `ADMIN` или
  `SUPER_ADMIN`. Строка `'access-token'` в стор не попадёт, форма
  останется на экране, и тест «после входа видна шапка» упадёт при
  исправной форме.
- Оболочка и таблица маршрутов — общие с задачами 4 и 5. Эта задача
  заводит шапку с email и выходом. Задача 4 добавляет пункт навигации,
  задача 5 — ссылку на смену пароля. Ожидаемый порядок при конфликте
  записан в [README этапа](./README.md#почему-такой-порядок).
- Текст ошибки и email в шапке — обычные узлы React.
  `dangerouslySetInnerHTML` для них не используется.

## Объём работы

- Маршруты на том API роутера, которое выбрала задача 3 этапа 0:
  - без сессии любой путь показывает логин (неизвестный адрес до входа
    не рисует отдельную карту приложения);
  - с сессией `/` показывает оболочку и короткую русскую фразу, что
    рабочие экраны ещё впереди;
  - с сессией неизвестный путь показывает ту же оболочку и русскую
    пометку, что адреса нет;
  - с сессией заход на логин возвращает на `/`.
- При старте приложения, если хранилище содержит refresh, один вызов
  восстановления из задачи 2. Форма монтируется только после него, и
  только если сессии так и нет.
- Форма: email, пароль, отправка через метод логина. Ошибка сервера
  (`401`, `400` с массивом `message`, `429`) видна на форме. Успех
  оставляет человека в оболочке. Поля MUI, подписи на русском.
- Шапка при сессии: «Админка QuizBeat», email из стора, кнопка выхода.
  Без сессии в шапке только название.
- Если в хранилище остался email (отказ refresh его сохраняет), поле
  логина заполнено им.
- Тесты Testing Library:
  - без refresh на `/` видны поля и заголовок, выхода нет;
  - логин с моком `200` показывает email в шапке и прячет форму;
  - логин с моком `401` показывает `Invalid credentials` и остаётся на
    форме;
  - логин с моком `429` показывает `message` и не шлёт второй запрос;
  - старт с сохранённым refresh вызывает восстановление один раз и при
    `200` открывает оболочку, не мигая полями логина в том же тесте
    (поля отсутствуют после завершения восстановления);
  - выход возвращает форму, и повторный рендер с тем же хранилищем
    восстановление не зовёт, потому что refresh уже стёрт.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`, включая
  обновлённый случай оболочки этапа 0. Пропущенных тестов на логин нет.
- `npm run lint` и `npm run build` проходят: в сборке есть маршрут логина.
- В компонентах формы нет строки `/auth/staff`: запросы остаются в
  модуле задачи 2. Проверяется поиском по каталогу экрана.
- Ручной проход против живого сервера в эту задачу не входит — его
  делает [задача 6](./06-step1-acceptance.md). Здесь достаточно тестов
  на моке.
