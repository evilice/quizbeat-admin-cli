## Зачем

DoD этапа держится на форме: без обоих названий запрос не уходит, с
обоими — уходит и потом находится поиском. Создание и правка делят одни
и те же три поля. Две задачи собрали бы это правило дважды и правили бы
один диалог. Удаление сюда не входит: у него другое подтверждение и
пустой `204`, без тела с переводами. Пока нет списка из задачи 2, форму
некуда поставить и после успеха нечего обновлять.

## Границы задачи

| Входит | Не входит |
|---|---|
| Одна форма на создание и правку: код, название `ru`, название `en` | Удаление — [задача 4](./04-delete-tag.md) |
| `POST /tags` и `PATCH /tags/:id` с полным набором из двух локалей | Второе поле перевода под именем `text`. Так устроены заметки, их экран — [этап 7](../../03-technical-specification.md#этап-7--заметки-а-знали-ли-вы) |
| Пустой код или пустое название на сервер не уходят | Выбор тегов у композиции — [этап 4](../../03-technical-specification.md#этап-4--композиции) |
| `409` занятого кода на форме | Отдельный маршрут `/tags/:id`. Чтения одного тега на сервере нет |

## ⚠ Технические нюансы и ограничения

- Форма одна, два входа: кнопка «Создать» и действие «Изменить» на
  строке. Правка заполняется из строки, которая уже есть на экране:
  код и оба названия по полю `locale`, не по индексу массива. См.
  [решения этапа](./README.md#решения-по-открытым-вопросам-этапа).
- Создание отправляет `{ code, translations }` из двух элементов,
  локали `ru` и `en`, у каждой поле `name`. Правка отправляет тот же
  состав на `PATCH /tags/:id`, даже если человек изменил только одно
  название. Опустить `translations` значит оставить на сервере прежний
  набор при уже других полях на экране. Отправить одну локаль — `400`.
- Пустой код или пустое любое из двух названий на сервер не
  отправляется, на форме русское сообщение. Пробелы по краям клиент не
  обрезает и регистр кода не меняет: уникальность `code` на сервере
  чувствительна к регистру. Если сервер всё же ответил `400` и
  `message` массивом, форма показывает весь список через уже
  существующий разбор ошибки.
- Занятый код — `409` и `message` `Tag with this code already exists`.
  Форма показывает эту строку как есть, диалог остаётся открыт, список
  заново не запрашивается, поля не очищаются так, будто запись прошла.
  Тот же текст и на создании, и на правке.
- Успех создания — `201`, успех правки — `200`. Диалог закрывается,
  список перечитывается тем же запросом, который уже на экране (тот же
  поиск и та же страница). Ответ в таблицу в обход этого чтения не
  вставляется. Если поиск был по старому названию, строки после правки
  на текущей странице может не быть.
- Экран списка общий с задачей 4. Эта задача добавляет кнопку создания
  и правку строки и не добавляет удаление. При конфликте слияния она
  идёт сразу после задачи 2, см.
  [README](./README.md#почему-такой-порядок).

## Объём работы

- На списке кнопка «Создать» открывает форму с пустыми полями. На строке
  действие «Изменить» открывает ту же форму, заполненную кодом и обоими
  названиями этой строки. Подписи русские.
- Отправка создания вызывает метод стора с `{ code, translations }`.
  Отправка правки вызывает метод правки с id строки и тем же составом
  тела. Проверка до запроса: пустой код или пустое название `ru` или
  `en` — русское сообщение, `fetch` не вызывается.
- При `201` и при `200` диалог закрыт, список запрошен заново с текущим
  поиском и страницей. При `409` на форме видна строка
  `Tag with this code already exists`, диалог остаётся открыт.
- Тесты:
  - пустое название `en` при заполненных коде и `ru` не вызывает
    `fetch`; то же для пустого `ru` и для пустого кода;
  - создание шлёт две локали с полем `name` и не шлёт `text`;
  - правка, в которой изменено только русское название, шлёт и `ru`, и
    `en`;
  - `201` закрывает диалог и вызывает повторное чтение списка;
  - `409` с текстом про занятый код показывает эту строку и не
    запрашивает список заново.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят.
- В модуле формы есть поле `name` у обоих переводов и нет поля `text`.
  Проверяется чтением формы.
