`originalAudioDurationSec` в памяти экрана после `201`); методы

Ссылка на ТЗ: [раздел «Этап 5»](../../03-technical-specification.md#этап-5--аудио-и-отрезки)

## Зачем

DoD этапа требует отметить точки на композиции с треком. Длительность
ограничения — серверная; URL волны — только временный `GET .../audio`.
Отдельная задача удерживает выбор библиотеки волны и сборку `points`
вдали от multipart и от таймера опроса.

## Границы задачи

| Входит | Не входит |
|---|---|
| Отображение волновой формы по `originalAudioUrl` из состояния карточки (первое открытие) / из ответа `GET .../audio` (обновление протухшей ссылки) | Загрузка файла — [задача 2](./02-audio-upload.md) |
| UI разметки: старт (целое секунд), `durationSec` из `1, 2, 3, 5, 8, 13, 21`, `difficulty` `EASY` / `MEDIUM` / `HARD` | Список, опрос, плеер отрезка — [задача 4](./04-clips-list-and-poll.md) |
| Клиентский запрет точки с `start + duration > originalAudioDurationSec`; отправка `{ points }` (≥ 1) | Удаление и перегенерация — [задача 5](./05-clip-delete-and-regenerate.md) |
| Пометка / скрытие формы разметки, если трека ещё нет (`originalAudioDurationSec: null`) | Собственный `GET /full` — этот блок его не вызывает, читает данные, уже полученные карточкой (этап 4) |
| Выбор и установка библиотеки волны по тайпингам установленной версии | Имя библиотеки и пропы «по памяти» в этой задаче не зафиксированы заранее — см. README |

## ⚠ Технические нюансы и ограничения

- Длительность и URL — решения
  [README](./README.md#решения-по-открытым-вопросам-этапа). Кратко: при
  первом открытии карточки оба поля уже в её состоянии (ответ `full`, F5
  их тоже отдаёт); не брать длительность из элемента `<audio>` / API
  волны; не класть `url` в состояние насовсем; при протухании ссылки —
  снова `GET .../audio`.
- Пока `originalAudioDurationSec` в состоянии карточки — `null` (трек не
  загружен), форма разметки не шлёт `POST .../clips` и может быть
  скрыта / неактивна. После загрузки трека это состояние есть всегда,
  включая перезагрузку страницы — отдельного «временного» ограничения
  здесь больше нет.
- `startTimeSec` уходит целым. Пустой набор точек кнопку отправки не
  активирует / не вызывает `fetch`.
- Отказ сервера (`400` out of range, `409` нет оригинала) — `message` на
  блоке, сессию не чистить.
- Библиотека: добавить зависимость только в этой задаче, свериться с
  типами в `node_modules` установленной версии (правило 4). В
  декомпозиции пакет не назван.
- Общий файл карточки: после задачи 2, до задачи 4 при конфликте
  слияния.

## Объём работы

- Отрисовать волну по `originalAudioUrl` из состояния карточки; при
  протухшей ссылке — обновить её `GET .../audio` и перерисовать.
- Форма / взаимодействие: добавить одну или несколько точек (старт,
  длительность из фиксированного набора, сложность), удалить точку из
  черновика до отправки.
- Нельзя подтвердить точку, если
  `startTimeSec + durationSec > originalAudioDurationSec` (когда
  длительность известна).
- Отправка вызывает метод стора с `{ points: [...] }`.
- Тесты:
  - сборка тела: есть ключ `points`, у каждой точки целый
    `startTimeSec`, допустимые `durationSec` и `difficulty`;
  - точка за границей длительности не вызывает `fetch`;
  - пустой черновик точек не вызывает `fetch`;
  - `originalAudioDurationSec: null` в состоянии карточки не даёт
    отправить точки;
  - волна рисуется по `originalAudioUrl` из состояния карточки без
    собственного `GET .../audio` на маунте; протухшая ссылка обновляется
    им отдельно;
  - блок не вызывает `/full` сам.

## Критерии готовности

- Тесты из объёма работы проходят через `npm run test`.
- `npm run lint` и `npm run build` проходят (в сборке есть зависимость
  волны, если она добавлена).
- В коде разметки длительность для проверки границ читается из состояния
  карточки (заполненного ответом `full` при открытии и обновляемого
  ответом `201` после загрузки), а не из `HTMLAudioElement.duration`.
  Проверяется чтением модуля / тестом.
